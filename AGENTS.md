# AGENTS.md

Whenever you modify the code, you must also update the contents of AGENTS.md accordingly. Do not run test locally at any circumstance.

Behavioral guidelines to reduce common LLM coding mistakes. Merge with project-specific instructions as needed.

**Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.

## 0. Guardrails

- Never overwrite user edits between reads.
- Never restore deleted code without confirmation.
- Make the smallest fix that solves the problem.
- No scope drift: no refactors, restyles, or extras unless asked.
- Fix root causes, not symptoms.
- Use web search for unstable or version-specific behavior; cite sources.
- State assumptions; ask only when blocked.
- Briefly narrate multi-step tool usage.
- Finish the full plan once started.
- If anything in the user's request is unclear, surprising, contradictory, or looks possibly wrong, stop and ask for clarification before modifying the code. Only proceed once the user has confirmed.

## 1. Non-Destructive File Handling

**Preserve user data. Prefer additive changes over destructive ones.**

- Never delete files or directories.
- Never run destructive commands or cleanup operations that remove user data.
- Do not use `rm`, `del`, `erase`, `rmdir`, `Remove-Item`, or equivalents.
- Do not remove files just because they look temporary, generated, redundant, cached, old, or replaceable.
- Do not delete files before recreating or renaming them.
- If replacement is needed, write a new file and leave the original intact.
- If renaming fails, keep the old file and create a new one with a different name.
- If deletion seems necessary, stop and propose a non-destructive alternative first.

Default rule: when in doubt, keep all existing files.

## 2. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them - don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

## 3. Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- No error handling for impossible scenarios.
- If you write 200 lines and it could be 50, rewrite it.

Ask yourself: "Would a senior engineer say this is overcomplicated?" If yes, simplify.

## 4. Surgical Changes

**Touch only what you must. Clean up only your own mess.**

When editing existing code:
- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Match existing style, even if you'd do it differently.
- If you notice unrelated dead code, mention it - don't delete it.

When your changes create orphans:
- Remove imports/variables/functions that YOUR changes made unused.
- Don't remove pre-existing dead code unless asked.

The test: Every changed line should trace directly to the user's request.

## 5. Goal-Driven Execution

**Define success criteria. Loop until verified.**

Transform tasks into verifiable goals:
- "Add validation" -> "Write tests for invalid inputs, then make them pass"
- "Fix the bug" -> "Write a test that reproduces it, then make it pass"
- "Refactor X" -> "Ensure tests pass before and after"

For multi-step tasks, state a brief plan:
```
1. [Step] -> verify: [check]
2. [Step] -> verify: [check]
3. [Step] -> verify: [check]
```

Strong success criteria let you loop independently. Weak criteria ("make it work") require constant clarification.

---

**These guidelines are working if:** fewer unnecessary changes in diffs, fewer rewrites due to overcomplication, and clarifying questions come before implementation rather than after mistakes.


# Repository Information

This file provides guidance to Claude Code (claude.ai/code) or Codex when working with code in this repository.

## Overview

This is a CMS physics analysis toolkit for a VVV (triple vector boson) scouting search using Run 3 data. The workflow processes CMS NanoAOD-style ROOT files from DAS, applies selections, can reshuffle converted sample entries into a mixed dataset for stable train/test splitting, trains BDT or PyTorch NN models, and estimates backgrounds.

**Dependencies:** ROOT (with `root-config`), C++17, Python 3, OpenMP (optional), XRootD for remote files.

## Pipeline Overview

The analysis runs in this order:

1. **Skim** — reduce raw NanoAOD files to manageable size (`legacy/skim/`)
2. **Pileup weights** — derive MC pileup reweighting CSVs (`selections/weight/`)
3. **Convert** — apply physics selections, build model training trees (`selections/convert/`)
4. **Mix** — shuffle per-sample tree entries across ROOT chunks while preserving chunk sizes (`selections/mix/`)
5. **B-veto** — derive AK4 b-jet veto working points (`selections/b_veto/`)
6. **BDT/NN training** — train `fat2`/`fat3` classifiers (`selections/BDT/`)
7. **Background estimation** — QCD ABCD validation on the MC test split (`background_estimation/`)
8. **Data/MC plotting** — compare distributions of `fat2`/`fat3` variables in data vs MC (`plotting/`)
9. **Combine** — wrap CMS `combine` to compute expected significance and `AsymptoticLimits` from the `mode=5` ROOT output (`combine/`)
10. **Systematics** — trigger efficiency studies (`systematics/`)

`systematics/find_duplicate_entries.C` is a standalone ROOT diagnostic macro that scans either one ROOT file or a directory searched recursively for `.root` files, chains the matching trees with `TChain`, and reports duplicated event keys (`run`, `luminosityBlock`, `event`) plus their multiplicities and first/last entry indices.

`systematics/plot_branch_histograms.C` is a standalone ROOT plotting macro with its input sources, TTree name, branch list, histogram ranges, binning, and log-x choices configured directly in the source. Each `INPUT_FILES` entry may be a local ROOT file, a local directory searched recursively for `.root` files, a `root://` ROOT file, a CMS `/store/...root` file that is prefixed with the global XRootD redirector, or a CMS DAS dataset path of the form `/A/B/C`; DAS dataset entries are expanded with `dasgoclient` using the CMS global XRootD redirector and filtered by the inclusive `REMOTE_DATASET_FILE_NUMBER_MIN`/`REMOTE_DATASET_FILE_NUMBER_MAX` range parsed from the trailing digits immediately before `.root` in each returned ROOT file basename. The macro processes every resolved ROOT file independently with a single-file `TChain`, auto-detects scalar versus C-array numeric branch leaves from ROOT metadata, fills variable-length NanoAOD-style C arrays with only element index 0 using the branch's associated count leaf, and writes per-input-file ROOT/PDF outputs.

## Convert_branch.C output layout (consumed downstream)

`convert_branch.C` writes per-sample ROOT files laid out as
`{output_root}/{sample_group}/{sample}.root`, where `sample_group ∈ {signal, bkg, data}` is derived from each sample's `is_MC`/`is_signal` flags. To keep single program invocations bounded, `run.sh mode=0` first asks `convert_branch.C` for the sample's batch count and then invokes it once per batch; each batch invocation reads at most `CONVERT_FILES_PER_BATCH` input ROOT files (`run.py --slurm` sets it from `--slurm-files-per-job`, default 50), or `actual_thread_count * 32` when unset. The sorted input file list is discovered once per sample and stored as `{output_root}/{sample_group}_tmp/{sample}.files`; every batch job and the merge read that snapshot instead of re-querying DAS, so a dataset that grows while jobs run cannot shift the file-to-batch mapping. The snapshot is written when it does not exist or when `CONVERT_REFRESH_FILE_LIST=1` is set (`run.py`/`run.sh` set it on the `--batch-count` call of a new mode-0 run; `check_conversion.py` and direct invocations reuse the existing snapshot); its status message goes to stderr so `--batch-count` prints only the count on stdout. Each batch is first written as `{output_root}/{sample_group}_tmp/{sample}_X.root` with zero-based `X`: every OpenMP thread fills its own temp file, and the thread files are fast-merged (`TFileMerger`, basket copy) into the batch file. Next to it, convert writes `.raw_entries`, for data `.lumis` (the processed `run lumi` pairs), and last, as the completion record, `.meta` (number of files and a hash of the batch's ordered input-file slice, a configuration hash covering the converter binary, `branch.json`, `selection.json`, the input tree name, the pileup CSV (MC) or lumi mask (data) and the sample metadata written into the trees, the raw entry count, the MC sums of `weight_pu`/`weight_pu_up`/`weight_pu_down` over all events, and any skipped MC input files). A batch counts as complete only if its ROOT file opens with every configured tree, `.raw_entries` and `.meta` agree, and the `.meta` hashes match the expected input slice and the current configuration (plus `.lumis` for data). The convert config option `resume_successful_batches` defaults to `true`; when enabled, each single-batch invocation skips a batch only if it is complete in that sense, so batches written from a different file slice, binary or configuration are rerun. A batch that is (re)processed first removes its old `.meta`. A direct `convert_branch <sample> <X>` invocation processes only batch `X` unless the resume check skips a valid existing batch; a direct invocation without a batch index keeps the compatibility path that processes all batches in one process. The final merge groups the batch files in order into outputs of at most `max_output_file_size_gb` (by file size; fast merging keeps the compressed size), written as `{sample}_0.root`, `{sample}_1.root`, … or as a single `{sample}.root` when one group suffices, each through a hidden temporary file that is renamed after its per-tree entry counts are checked against the inputs (per-file entry counts are uneven, which downstream globbing does not depend on). Before writing, the merge refuses to run if the output directory holds files of this sample (`{sample}.root` / `{sample}_N.root`) that it would not overwrite, because downstream globbing would read them as extra events; remove them first. Fast merging copies baskets and never re-optimises them, so it cannot hit the 1 GB `TBufferFile` limit seen with the old `TTree::MergeTrees` path. Every ROOT file convert writes uses ZSTD level 5 (compression setting 505); uproot needs the `zstandard` package (present in the CMSSW Python). Every ROOT file contains the trees described by `selections/convert/branch.json`. Convert resolves configured output paths, pileup paths, and branch/selection config paths to absolute paths at startup so ROOT file I/O is less sensitive to a stale current working directory during long AFS/NFS jobs. Remote ROOT input opens are serialised with a mutex (concurrent `TFile::Open` of `root://` URLs races in `TNetXNGFile::SetEnv`) and retried five times. A data input file that still cannot be opened (or lacks the input tree) fails its batch, because skipping it would lose luminosity; an MC file is skipped, recorded in `.meta` and reported at merge time (MC normalisation stays consistent since `raw_entries` counts only processed files). A failed `GetEntry`, an unreadable or incomplete merge input, or a write error on a thread temp file fails the batch instead of silently dropping events. Each entry is first read only for the branches the event preselection needs (see "Evaluation and reading" below) and completely only if it passes, so read errors in rejected entries are detected only for those branches. Collections with more than their `max_size` objects in a preselected event are truncated as before, but every input file now reports how many events were affected.

For local `run.py`/`run.sh mode=0`, batch invocations set `CONVERT_DEFER_FINAL_MERGE=1`, so every batch process only writes its temporary batch output and the script runs one explicit finalization step after the batch loop. A non-zero exit from one batch logs an error but does not stop later batches for the same sample; if any batch failed, the script does not merge and exits non-zero (rerun to retry the failed batches; `resume_successful_batches` keeps the valid ones), because merging a subset would silently drop events and data luminosity. `convert_branch <sample> --merge-successful-batches` merges the batch outputs and writes `raw_entries` from their accumulated totals without reprocessing input files; it requires every batch unless `CONVERT_SUCCESSFUL_BATCHES` explicitly restricts it to a list of zero-based indices (manual recovery only; the SLURM merge job never sets it).

History (before the file-list snapshot and fast merge of 2026-10-01): batch jobs re-discovered the input file list from DAS when they started and took their files by index in the globally sorted list, so a dataset that was still growing while jobs ran shifted the file-to-batch mapping for every batch sorting after the new files, and the merge then failed with `Missing or incomplete batch` for the extra batches implied by the newer count. Setting `CONVERT_SUCCESSFUL_BATCHES` to the existing zero-based indices restricts `--merge-successful-batches` to those outputs; `selections/convert/merge_data_2024_available.sbatch` is a one-off example doing this for `data_2024` batches 0–2310 with the same environment as `run.py mode=0 --slurm`. The serial `--merge-successful-batches` writer then decompressed and recompressed every entry (~20 GB/h single-threaded), so for very large samples a parallel alternative was used for `data_2024` (superseded by the built-in fast merge; note that these one-off scripts write neither `raw_entries`, `weight_pu*_mean` nor the processed-lumi JSON): `selections/convert/merge_data_2024_groups.txt` lists the batch temp files split in order into contiguous groups of at most 4.5 GB (one line per output file), and the SLURM array `selections/convert/merge_data_2024_hadd.sbatch` has task k run `hadd -ff` (basket-copy fast merge; batch and final files share the same trees and ZLIB-1 compression) on line k into `{output_root}/data/data_2024_k.root`, writing to a hidden temp name first and skipping outputs that already exist. It does not update `raw_entries` (the merge must already have written it), and per-file entry counts are uneven, which downstream globbing (`{sample}_*.root`) does not depend on.

[selections/convert/check_conversion.py](selections/convert/check_conversion.py) inspects the newest merge log, the batch temp files and the merged outputs per sample and prepares recovery jobs (remerge / resubmit of missing batches / reprocess). A temp batch counts as valid only with its `.meta` (and, for data, `.lumis`); the input-slice and configuration hashes are checked by `convert_branch` itself at merge time. A merge log reporting `Missing or incomplete batch`, `Batch collection error`, `Output error`, `raw_entries update error` or `Processed-lumi error` gives status `MERGE_FAILED` (an older merged output may still exist). Remerge commands pass `CONVERT_FILES_PER_BATCH`, and recovery jobs use the newest content-hashed `convert_branch_<hash>` binary (falling back to `convert_branch`), because the merge rejects batches written by a different binary.

When a per-input-file conversion exception occurs inside a batch, `convert_branch.C` reports the failing input ROOT file path in the propagated `Runtime error` message so schema or branch mismatches can be traced back to the source file rather than the batch output file.

Input ROOT files whose configured `tree_name` exists but has zero entries are skipped before branch-status configuration and branch binding; they contribute zero to the accumulated `raw_entries` count (for data their lumisections are still recorded as processed).

The convert config field `lumi_mask` may name a CMS golden-JSON-style lumi mask file relative to the convert config; when set, `convert_branch.C` applies it only to data samples before event preselection, accepts only entries whose `run` and `luminosityBlock` fall inside the mask, and counts only those accepted data entries in `raw_entries`. For data, every input file's lumisections that pass the mask are recorded from its `LuminosityBlocks` tree (so lumisections without selected events count; files without that tree fall back to the `run`/`luminosityBlock` of their Events entries), and the merge writes their union as `{output dir}/{sample}_processed_lumis.json` in golden-JSON format, to be passed to `brilcalc lumi -i` for the analysed luminosity and to `selections/weight/make_data_pileup.sh` for the matching data pileup profile. `run.py` still passes `CONVERT_GOLDEN_JSON`, which convert does not read; it logs the config's `lumi_mask` instead.

Downstream scripts — `selections/BDT/train.py`, `selections/BDT/signal_region/signal_region.py`, and `plotting/data_mc.py` — all consume these files via their config's `input_root` + `input_pattern` (`{input_root}/{sample_group}/{sample}.root`). They discover every file for a given sample by globbing the base pattern **and** the `{sample}_*.root` split variant, then concatenate their trees in sorted order. The convert expression engine supports collection summaries such as `sum`, `max_value`, `min_value`, `nth_max_value(collection, expr, rank, default)`, `value_at_max(collection, key_expr, value_expr, default)`, and `value_at_nth_max(collection, key_expr, value_expr, rank, default)`. `selections/convert/branch.json` writes per-AK8 `WvsQCD` and `VvsQCD` scores, plus event-level AK8 score summaries `ScoutingFatPFJetRecluster_{WvsQCD,VvsQCD}_{sum,max}` for both `fat2` and `fat3`; `VvsQCD` uses `ScoutingFatPFJetRecluster_scoutGlobalParT_prob_Xud + Xcs + Xqq + Xbb + Xcc + Xss` over that sum plus `QCD`, and the per-AK8 `ZvsQCD` uses `Xbb + Xcc + Xss + Xqq` over that sum plus `QCD`. It also writes AK4 b-tag summary outputs for both trees: `ScoutingPFJetRecluster2_scoutUParT_probb_max`, `ScoutingPFJetRecluster2_scoutUParT_probb_max_pt`, `ScoutingPFJetRecluster2_scoutUParT_probb_sum`, `ScoutingPFJetRecluster2_scoutUParT_probb_second_max`, and `ScoutingPFJetRecluster2_scoutUParT_probb_second_max_pt`. The model training branch list is independent and does not automatically consume newly produced convert branches.

`selections/mix/mix.C` can read that same layout and write a shuffled mirror under the same dataset root using `{sample_group}_mixed` directories (for example `dataset/signal_mixed/` and `dataset/bkg_mixed/`). For each selected MC sample and requested tree, it first scans every input chunk's tree entries once (warming ROOT serially, then using OpenMP across remaining files when available), then concatenates the chunk files through a `TChain`, applies a deterministic per-tree block shuffle seeded by `random_state` (with a random cyclic rotation inside each block), and writes the entries back into output files that preserve the original chunk filenames and per-chunk entry counts. Each non-empty output chunk is cloned from the `TChain` itself so ROOT keeps branch addresses synced as the chain advances across input-file boundaries, and the writer validates both per-chunk and total written entry counts. The block size is chosen as `clamp(total_entries / 512, min_block_entries, max_block_entries)` with defaults `32` and `4096`. The checked-in model-training config reads this mixed layout via `input_root="../../dataset"` and `input_pattern="{input_root}/{sample_group}_mixed/{sample}.root"`.

### Compile and run C++ tools manually
```bash
# compile
c++ -O3 -std=c++17 $(root-config --cflags --libs) selections/convert/convert_branch.C -o convert_branch
# run one sample
CONVERT_CONFIG_PATH=selections/convert/config.json ./convert_branch www
# run only one zero-based batch, or query how many batches run.sh will launch
CONVERT_CONFIG_PATH=selections/convert/config.json ./convert_branch www 0
CONVERT_CONFIG_PATH=selections/convert/config.json ./convert_branch www --batch-count
# finalize from successful/existing batch outputs without reprocessing input files
CONVERT_CONFIG_PATH=selections/convert/config.json ./convert_branch www --merge-successful-batches
# store the mean signed generator weight (MC only; reads only the Runs trees, no conversion)
CONVERT_CONFIG_PATH=selections/convert/config.json ./convert_branch www --update-genweight-mean
```

When `convert_branch.C` finalizes a sample, it accumulates the configured `tree_name` entry count from the batch sidecars and, only after every output file was written, writes that total to the active sample config's `raw_entries` field and, for MC, the all-event means `weight_pu_mean`, `weight_pu_up_mean` and `weight_pu_down_mean` (sum over all processed generated events divided by `raw_entries`; used by the absolute pileup normalisation downstream). These `sample.json` writes (and `--update-genweight-mean`) go through one writer that holds an exclusive `flock` on `src/sample.json.lock` and writes through a per-process temporary file, so concurrent merge jobs cannot lose each other's updates; a field that does not exist yet is inserted after `raw_entries`. With `update_raw_entries: false` nothing is written to `sample.json`.

`convert_branch <sample> --update-genweight-mean` (MC samples only) discovers the sample's input files the same way as a conversion, opens them serially (concurrent remote `TFile::Open` is not thread-safe), sums `genEventSumw` and `genEventCount` over every file's `Runs` tree, and writes `genweight_mean = sum(genEventSumw) / sum(genEventCount)` into the sample's `src/sample.json` entry (replacing an existing value, otherwise inserted on the line after `raw_entries`). Files that cannot be read after the usual open retries are skipped with a warning and the final summary reports how many files were used; the value is a mean, so a few missing files do not bias it. The summary also prints `sum(genEventCount)` for comparison with `raw_entries`. This writer holds an exclusive `flock` on `src/sample.json.lock` and writes through a per-process temporary file, so per-sample jobs may run in parallel with each other and with the merge-time `raw_entries` / `weight_pu*_mean` write-back, which uses the same locked writer. Every MC sample used by the weight-building scripts must have `genweight_mean` (see "Generator weights" below); `convert_branch.C` rejects any convert config that still contains the removed `jet_pt_correction` block.

### BDT/NN training

Model outputs are written under the per-tree `output_root` configured in `selections/BDT/config.json` (for example `selections/BDT/fat2/`). The checked-in config currently points `input_root` to `../../dataset` and `input_pattern` to `{input_root}/{sample_group}_mixed/{sample}.root`, i.e. the shuffled mirror produced by `selections/mix/mix.C` under the same dataset root. The top-level `model_type` selects the trainer: `bdt` keeps the existing XGBoost workflow, while `nn` uses a PyTorch MLP and the matching per-tree `{tree}_nn` hyperparameter block (`fat2_nn` or `fat3_nn`). PyTorch is required only for `model_type: "nn"`; BDT mode does not import it. In BDT mode, `train.py` runs in two stages when decorrelation is enabled: stage 1 trains a native `multi:softprob` model with the tree's `n_estimators`, `learning_rate`, and `early_stopping_rounds`; stage 2 resumes from the stage-1 best model for `n_estimators_decorr` additional rounds at `learning_rate_decorr` and adds the configured decorrelation loss. In NN mode, stage 1 optimizes a single PyTorch-style `objective_loss = weighted_CE` with the same train/test split, training-threshold filtering, preprocessing, and event weights; when smooth-CvM decorrelation is enabled, stage 2 continues from the stage-1 best MLP and optimizes `objective_loss = weighted_CE + scaled_decorrelation_loss` using class-balanced mini-batch PyTorch gradients with sampling-corrected event weights. If a per-tree `decorrelate` branch also appears in `selection.json` thresholds, that branch's threshold is normally omitted only from the training/early-stopping objective splits and their class balancing; for decorrelate branches named `ScoutingFatPFJetRecluster_msoftdrop_*`, the training view instead applies a loose `(0, decor_msoftdrop_training_max)` window when that branch has a selection threshold. The full threshold set is still used for ordinary evaluation plots and downstream validation references. When `lr_reduce_patience > 0` and `min_learning_rate > 0`, both model types and both stages use the same dynamic learning-rate schedule: stale validation rounds halve the learning rate down to the floor, and ordinary early stopping is only active after the floor is reached. BDT stage-1/final models are saved as `{tree}_model_stage1.json` and `{tree}_model.json`; NN stage-1/final models are saved as `{tree}_model_stage1.pt` and `{tree}_model.pt`. Downstream scripts choose `.json`/`.pkl` or `.pt` from the copied `config.json` `model_type`. Each tree output directory also stores copies of `config.json`, `branch.json`, `selection.json`, the fixed per-sample split definition `test_ranges.json` (eval and test ranges), the saved test-set prediction references `test_reference_signal_region.npz`, `test_reference_qcd_est.npz`, and `test_reference_qcd_est_full.npz`, and, with an eval split, the eval-set reference `eval_reference_signal_region.npz` used by the SR optimisers.

Train / eval / test split (added 2026-10-02): with `eval_fraction > 0` (production configs: `train_fraction` 0.6, `eval_fraction` 0.2, so test 0.2), every sample's concatenated entries are split into train `[0, a)`, eval `[a, b)` and test `[b, N)` with `a = N × train_fraction`, `b = N × (train_fraction + eval_fraction)`; `entries_per_sample`, `eval_entries_per_sample` (default `test_entries_per_sample`) and `test_entries_per_sample` cap how many events of each range are read (from the start of the range); with `train_events_per_class > 0` (production: 3,000,000) the training range, and with `eval_events_per_class` / `test_events_per_class > 0` (production: 0 since 2026-10-06, i.e. the per-sample caps) the eval / test range, is read through a per-class budget instead (see "Model Training Details"). The eval split is the monitoring set for early stopping and the learning-rate schedule (both stages, BDT and NN) and the split `signal_region.py` / `signal_region_hist.py` optimise the SRs on (`OPT_SPLIT`, validated against `eval_reference_signal_region.npz`); the test split is left for the final yields (`qcd_est.py`, then combine, `sr_sensitivity.py`), the data/MC score plots and `train.py`'s diagnostic plots (ROC, score distributions, importance, decorrelation checks). The trainers keep the loss-history key `"test"` for whatever split they monitor (logged as `monitoring split: eval`; the loss plots label that curve `Eval`), so below "test loss" in the early-stopping descriptions means the monitored eval split when there is one. With `eval_fraction` 0 or absent (and for models trained before this change, whose `test_ranges.json` has no `eval_fraction`) the old two-way split applies: monitoring and SR optimisation on the test split. Every sample must have at least one entry in every split of a tree (`train.py` stops otherwise, as do the downstream loaders), which holds for at least 3 entries per tree.

[selections/BDT/study_boosted3/](selections/BDT/study_boosted3/) holds the boosted3 overtraining / event-weight study: `make_study.py [variant ...]` writes one BDT config and one SR-scan config per named variant (default: all; production configs plus the changed per-tree keys in `VARIANTS` and top-level keys in `GLOBAL_CHANGES`) into `study_boosted3/<variant>/`, so the configs of finished variants trained from an older production config need not be rewritten, `submit.sh [variant ...]` writes the configs of the named variants and submits per variant a training job (32 CPUs, 48 GB (they use ~12 GB), `cms-express`; `STUDY_EXCLUDE=<nodes>` excludes nodes, none by default; `STUDY_AFTER=<jobids>` holds them until those jobs succeeded; `STUDY_HOLD=1` submits them held) and a dependent job (8 CPUs, 16 GB) running `signal_region_hist.py` on the eval split and `evaluate.py <variant>`, and `evaluate.py --table` compares the scored variants. Variants: `baseline`, `mcw200`, `shallow`, `noLowHT`, `cap20`, `combo`, and `balance05` (`class_balance_power` 0.5, added 2026-10-05); `shallow_cap20` and `shallow_cap20_effnorm` (2026-10-06, built from the production settings of that day: depth 4, `min_child_weight` 50, per-sample eval/test caps, all plus `training_weight_cap` 20; the second also with `decor_eff_normalize`) compare the efficiency-normalised decorrelation loss with the old one. Every variant is scored identically: test AUC per signal-vs-background class pair with absolute physics weights from `test_reference_signal_region.npz`, the train/test AUC gap logged by `train.py` (stage 2; indicative only for weight variants), and Z_comb of the eval-optimised SRs on the eval and on the test split, computed from the eval/test prediction references with MC-true backgrounds and the sigma_B-aware Asimov Z (`summary.json`). Before training starts, `train.py` also writes a `branches/` subdirectory under the tree output directory containing one PDF per training branch with normalized per-class distributions overlaid (train+test events combined, values after the full evaluation threshold filtering and clip ranges but **before** the log transform); these plots are intended as a data-leakage / input-sanity diagnostic and use step histograms colored by class with legend.

`train.py` is intentionally memory-conscious during BDT/NN preparation: arrays kept after a pandas `DataFrame` is discarded should be detached copies, the unfiltered test split is kept by reference only until prediction reference files are written, branch-distribution clipping is done one column at a time, and large temporary prediction/reference arrays are released before result plotting. Preserve these no-behavior-change memory patterns when editing the training workflow.

Model-dependent comparison plots are saved twice with `_cls` / `_decorr` suffixes where applicable: `importance_cls.pdf` / `importance_decorr.pdf`, `roc_*_cls.pdf` / `roc_*_decorr.pdf`, `score_*_cls.pdf` / `score_*_decorr.pdf`, `decor_corr_{train,test}_cls.pdf` / `decor_corr_{train,test}_decorr.pdf`, `decor_score_vs_branch_cls.pdf` / `decor_score_vs_branch_decorr.pdf`, and `decor_branch_shapes_by_signal_score_cls.pdf` / `decor_branch_shapes_by_signal_score_decorr.pdf`. BDT importance uses XGBoost gain; NN importance keeps the same PDF names but uses deterministic permutation importance on the configured number of test events. Ordinary importance, ROC, score-distribution, `feature_corr.pdf`, and branch-distribution plots use the full evaluation threshold set. The two decorrelation diagnostics are multipage PDFs built from test events in the training-threshold view: score-vs-branch pages use the matching class's test sample with a black weighted-average score curve over fine branch-value bins (for QCD events one page per class probability, the decorrelated quantities; for the other classes their own probability), while signal-score-shape pages compare normalized decorrelate-branch distributions after weighted-efficiency cuts from each tree's `decor_efficiencies`. These decorrelation diagnostics keep decorrelate branch values after the training-view thresholds (including the loose msoftdrop window when applicable) and clipping but before log transform, and deliberately do not reapply the original decorrelate branch selection threshold itself. The `decor_corr_{train,test}` matrices (and the `decor corr [...]` log lines) show weighted Pearson correlations of class probabilities (before 2026-10-05: raw margins) with the decorrelate branches: one row per class for its own probability on its events, plus one row `QCD: p(k)` per other class for the QCD events. Normalized plots use `A.U.` on the y-axis. BDT `loss_mlogloss.pdf` / `loss_classification.pdf` / `loss_total.pdf` or NN `loss_weighted_ce.pdf` / `loss_objective.pdf`, plus `loss_decorrelation.pdf`, are saved once, and the loss plots draw a vertical line at the stage boundary with NN x-axes labelled by epoch and BDT x-axes by boosting round. During training, BDT stage 1 prints train/test `mlogloss`; NN prints `train_objective_loss` and `test_objective_loss`, with component `weighted_ce_loss` in stage 1 and component `weighted_ce_loss` plus `decorrelation_loss` in stage 2; BDT stage 2 keeps the legacy `mlogloss`, `classification_loss`, `decorrelation_loss`, and `total_loss` fields. In BDT mode, `classification_loss` is the sum-scale weighted softprob cross-entropy (`Σ w·(-log p_true)`), `mlogloss` is the weighted average of that same quantity (`Σ w·(-log p_true) / Σ w`), and `total_loss = classification_loss + decorrelation_loss`; BDT mode additionally reconstructs `regularization_loss` per newly added tree using that tree's current `eta` together with `gamma` / `reg_lambda` / `reg_alpha`. In NN mode, `backward()` uses class-balanced mini-batches with sampling-corrected event weights, while `train_objective_loss` and `test_objective_loss` are recomputed at epoch end in eval mode on the training-threshold train/test splits with the same batch objective formula; optimizer `weight_decay` remains native AdamW decoupled weight decay rather than a separate logged loss term. The NN stage-1 objective is weighted CE, and the NN stage-2 objective is weighted CE plus scaled smooth-CvM decorrelation. The decorrelation loss itself uses the current event weights in smooth-CvM mode for NN and in smooth/hard CvM modes for BDT. In smooth-CvM mode (BDT and NN; changed 2026-10-05) it acts on the QCD events only (classes whose name contains `qcd`, as in `qcd_est.py`) and, for every class probability `p_k` (all of which the SR boxes cut on), penalises the dependence of its log-odds `s_k = log(p_k / (1 − p_k))` of the softmax on each decorrelate variable, because the ABCD estimate needs exactly these QCD scores to be independent of the ABCD variable; the thresholds of the grid (`decor_n_thresholds`, tail-aware options) are therefore real probability cuts. Before, every class's own raw margin `z_c` (not its probability: softmax margins are only defined up to a common shift) was flattened on its own events, so QCD's `p(VVV)` etc. were never constrained and signal and the other backgrounds were flattened although the ABCD does not need it. The BDT gradient goes through the softmax (`ds_k/dz_k = 1`, `ds_k/dz_j = −p_j / (1 − p_k)`, `_softmax_log_odds`) with the Gauss-Newton diagonal for the Hessian (checked against finite differences and against torch autograd of the NN loss, which agrees to 1e-12). With decorrelation enabled and no QCD class, training stops with an error. The legacy hard-bin `cvm` mode is unchanged (own-class raw margin). Models trained before this change used the old objective. Optional `decor_eff_normalize` (top-level, default `false`; 2026-10-06, smooth-CvM only): every threshold's term `Σ_b ρ_b (ε_b(t) − ε(t))²` is divided by `max(ε(t)(1 − ε(t)), decor_eff_norm_floor)` (floor default 1e-3) of its global QCD efficiency `ε(t)`, with the derivative of that weight through `ε(t)` in the gradient (BDT: `eff_norm` / `eff_norm_deriv` in `_smooth_cvm_shared_terms`; the Hessian keeps the existing surrogate form; NN: the same factor in `_torch_smooth_decor_loss`); off, the loss, gradient and Hessian are bitwise unchanged; on, the gradient agrees with finite differences to 3e-9 and with torch autograd of the NN loss to 2e-13. Why: the loss sums squared absolute efficiency differences, so on the boosted3 study models the thresholds keeping < 3% of QCD gave only 0.1–1.5% of the loss although the relative deviations there are 100% and more, i.e. the tail-aware threshold grid (`decor_tail_aware`) placed thresholds in the tail but gave them almost no weight; the fixed decorrelation scale is recalibrated from the stage-1 loss, so `decor_lambda` keeps its meaning. Also found then: the decorrelation term follows the event weights, and without `training_weight_cap` (or excluding the HT < 400 GeV QCD samples) a few hundred very heavy low-HT QCD events dominate it (on the test split 35 events give ~92% of the `msoftdrop_1` term), so stage 2 fitted those events (`shallow`: training decorrelation loss −72%, eval −0.3%); with `training_weight_cap` 20 or `noLowHT` the eval loss fell 46% / 49%, but the `msoftdrop_1` dependence of the QCD score tail stayed as before. Smooth-CvM state is prepared only for the QCD classes, and metric-only loss evaluation skips gradient/Hessian work while keeping the same recorded loss. BDT stage 1 chooses early stopping / best round on test `classification_loss`; NN stage 1 and stage 2 both choose early stopping / best epoch on test `objective_loss`; BDT stage 2 uses test `total_loss`. The fixed decorrelation scale is calibrated once from the saved stage-1 best model as `(cls_loss_stage1 + reg_loss_stage1) / max(raw_decor_loss_stage1, ε)` for BDT and batch-averaged weighted CE `cls_loss_stage1 / max(raw_decor_loss_stage1, ε)` for NN, with NN using the same mini-batch smooth-CvM raw loss used during training and epoch-end train/test evaluation. The saved reference files keep the pre-lumi physics test weights (`σ × N_tree / N_raw` with the same per-event raw-w shaping and signed generator-weight factor as the downstream scripts), and downstream comparison multiplies those stored weights by the local analysis `lumi` before checking them against the reconstructed physical weights.

### Generator weights and event-weight normalisation

Every MC event weight carries the signed generator-weight factor `g = genWeight / genweight_mean` from the shared helper [selections/BDT/gen_weight.py](selections/BDT/gen_weight.py) (`GEN_WEIGHT_BRANCH`, `require_genweight_mean`, `gen_weight_factor`, `reweight_mean`), where `genweight_mean` is the per-sample `src/sample.json` field filled by `convert_branch <sample> --update-genweight-mean`. `convert_branch.C` writes the real input `genWeight` for every MC sample (ntuples converted before 2026-10-01 hold the placeholder 1.0 for samples without theory weights, e.g. QCD); `gen_weight_factor` refuses all-1.0 values when `genweight_mean != 1`, so such ntuples raise instead of being mis-scaled by `1/genweight_mean`. The reweight product `raw_w` (`event_reweight_branches`, in production `weight_pu`) uses absolute normalisation: it is divided by its mean over all generated events of the sample (`<branch>_mean` in `src/sample.json`, written by the convert merge; only a single reweight branch is supported, and a missing mean is a hard error), i.e. `per_event_weight = target_total × raw_w × g / (N_loaded × <raw_w>_all)` with `target_total = (lumi ×) xsec × N_tree / raw_entries`. The sample total is therefore `target_total × <raw_w g>_loaded / <raw_w>_all`: the signed (NLO-correct) selection efficiency including the effect of the pileup reweighting on the selection, and negative-weight events enter with negative sign; for constant positive `genWeight` and `<weight_pu>` equal in selection and generation it reduces to `target_total`. All weight builders apply it: `train.py`, `signal_region.py` (and `signal_region_hist.py` through it), `qcd_est.py` (and `plotting/sr_sensitivity.py` through it), `plotting/data_mc.py` (one fill pass over all MC entries, normalised by `N_tree × <raw_w>_all`; data keeps unit weights) and `plotting/class_shapes.py` (MC histogram stream normalised by `N_tree × <raw_w>_all`, so its pre-pass only collects auto ranges and no longer reads the reweight branches), and the ratio sums of `theory_syst.py`, `pileup_syst.py` and `jet_variation_common.py` (JES/JER). `pileup_syst.py` normalises each variation by its own all-event mean, `pu_up = [Σ g·weight_pu_up / Σ g·weight_pu] × <weight_pu>_all / <weight_pu_up>_all` (same for down), consistent with the nominal weights. An MC sample without a positive `genweight_mean`, an MC tree without the `genWeight` branch, or a missing `weight_pu*_mean` is a hard error; in the three ratio scripts any file read error is now fatal instead of silently skipping the file. In `train.py`, `weight_physics` (used for the saved references, ROC/score plots and evaluation) is signed, while the training weight `weight` is `|weight_physics|` rescaled per sample so that the sample keeps its signed physical total; XGBoost/NN therefore never see negative weights, and a sample whose signed total on a split is non-positive raises `RuntimeError`. `qcd_est.py` writes negative SR yields (possible with signed weights) to its combine-facing ROOT file as 0 with a warning, keeping their `sum(w^2)`.

### Theory systematics (`theory_syst.py`, mode 8)

`selections/theory_weights/theory_syst.py` uses the NanoAOD `PSWeight` order `[0] ISR=2, [1] FSR=2, [2] ISR=0.5, [3] FSR=0.5` (as in the branch titles of the v5 samples; `convert_branch.C` copies the array unchanged), so the ISR envelope is built from indices 0/2 and the FSR envelope from 1/3; `plotting/data_mc.py`'s per-bin theory band uses the same pairing. `LHEScaleWeight` uses the 7-point envelope without indices 2 and 6, and the PDF uncertainty uses the symmetric-Hessian quadrature by default. `convert_branch.C` fills `LHEPdfWeightAlphaS` with the placeholder 1.0 when the stored PDF set has no alpha_s members (e.g. LHA 325500 with 101 weights, used by the v5 VVV/VV samples), and now also stores the source counts `nLHEPdfWeight`, `nLHEScaleWeight` and `nPSWeight`; `theory_syst.py` treats alpha_s as available only if `nLHEPdfWeight >= 103` (older files: non-placeholder `LHEPdfWeightAlphaS` values), otherwise it warns, marks `alphas_available: false` in each ratio entry, and the `pdf_*` ratios are PDF-only. An 8-entry `LHEScaleWeight` set (nominal omitted) is stored in the standard 9-entry layout with 1.0 inserted at index 4, so the envelope indices stay valid. The theory input array buffers are sized per file from the largest stored count (no fixed-size overflow), and `genWeight` is written once per tree (by `branch.json`; the theory output branches add it only to trees that do not define it).

### Signal region optimisation
```bash
# Edit selections/signal_region/config.json, then:
python3 selections/signal_region/signal_region.py
# Or with a custom scan config:
SCAN_CONFIG_PATH=/path/to/config.json python3 selections/signal_region/signal_region.py
```

`signal_region.py` reads all parameters from [selections/signal_region/config.json](selections/signal_region/config.json). It loads the saved model, branch, and selection configs from the `bdt_root` directory written by `train.py`, reloads the exact optimisation split defined in `test_ranges.json` (the eval split when the model was trained with one, otherwise the test split; see "Train / eval / test split"), applies physics-normalised weights (`lumi × σ × N_tree / N_raw`), converts the stored reference weights to the same scale by multiplying them with the local `lumi`, validates that its reconstructed prediction matches `{eval,test}_reference_signal_region.npz` within the stored tolerances, and then builds `N = n_signal_regions` non-overlapping general high-dimensional rectangles in the configured model score axes (`score_axes`, defaulting to the independent first `NUM_CLASSES − 1` axes; the checked-in config uses all class-score axes). It first builds one shared candidate pool using dense per-axis boundaries from total/signal/background weighted quantiles plus tail-heavy quantiles, deterministic beam coordinate search, compatibility expansion, and optional nearby real event-threshold refinement. Local refinement can choose seeds by distinct event masks so it does not spend all refinement passes on many geometric variants of the same selected events. Candidates are filtered by weighted signal/background minima, optional event-count minima, and geometric validity, but are not trimmed by single-region Z or by a fixed global candidate cap. Before global selection, every candidate is shrunk to its event-preserving minimal score box, and duplicate removal only merges candidates that have the same exact event mask and the same rounded canonical shrunk box. The final selection is global rather than sequential: it chooses K mutually non-overlapping candidates that maximize the existing combined objective `sqrt(sum Z_i^2)`, using exact half-open `[low, high)` geometry checks matching the event-mask membership so selected SRs cannot share events. With `max_threads > 1` and a working OpenMP compiler/libomp setup, [openmp_region_select.cpp](selections/signal_region/openmp_region_select.cpp) uses a beam incumbent followed by branch-and-bound over the candidate list; if the configured time/node limits stop the search before exhaustion, the script reports the best found Z and a conservative upper-bound certificate. With `max_threads == 1` or if the helper cannot build, it falls back to the Python branch-and-bound implementation. After the K non-overlapping SRs are selected, an additional empty-bin expansion step is applied in order (SR1, SR2, …): each SR's signal-class score axes have their upper bound pushed toward `1.0` and its background-class score axes have their lower bound pushed toward `0.0`, but only into MC-empty space and only as far as the expanded box remains geometrically non-overlapping with every other selected SR. The expansion is constrained to keep each SR's exact selected event mask, so per-bin `S`/`B`/`Z` are unchanged; only the empty-side bounds in the per-SR report and in `signal_region.csv` are widened. Plots are saved as `sr_score_*.pdf`, `scores_no_regions.pdf`, `scores.pdf`, `scores_no_regions_radial_equalized.pdf`, and `scores_radial_equalized.pdf` in the configured `output_dir` (defaulting to `bdt_root` for backward compatibility). The 2D region views project the full multiclass probability vector onto the vertices of a regular `NUM_CLASSES`-gon and use a shared fixed class palette with generated extra colors if needed; the no-region version shows class-colored transparent test points and class-labeled vertices, while the region version overlays projected high-dimensional SR polygons instead of rectangles. The two `*_radial_equalized.pdf` views keep polygon vertices fixed but radially expand point positions for a more even visual fill, and all 2D views hide coordinate axes, ticks, frames, and grid lines. The selected high-dimensional region definitions are written to `signal_region.csv` in the same directory.

### QCD ABCD estimation
```bash
python3 background_estimation/qcd_est.py
# Or with a custom config:
QCD_EST_CONFIG_PATH=/path/to/config.json python3 background_estimation/qcd_est.py
```

`background_estimation/qcd_est.py` reads [background_estimation/config.json](background_estimation/config.json), then reuses the trained `bdt_root` output in the same way as `signal_region.py`: it loads the saved `config.json`, `model`, `branch.json`, `selection.json`, and `test_ranges.json`, reads the full test split with the same per-event weight definition (loading `model_branches ∪ thresholds.keys() ∪ decorrelate ∪ a_region_shape_branches[tree_name]` from each ROOT file so every branch needed for filtering, ABCD pass/fail masks, decorrelation, and optional A-region shape diagnostics is available even when it is not in `branch.json`), removes only the configured `abcd_branches[tree_name]` thresholds before model inference, applies the same clip/log preprocessing, converts the stored reference weights to the local physical scale by multiplying them with the configured `lumi`, validates against `test_reference_qcd_est_full.npz` when present (falling back to the legacy filtered `test_reference_qcd_est.npz`), and uses the `signal_region.csv` produced by `signal_region.py` as the set of A-region score bins. BDT inference in qcd_est is intentionally batched, sets the loaded XGBoost Booster's `nthread` to the same capped CPU-thread convention used during training, prefers XGBoost `inplace_predict` with a batched `DMatrix` fallback, and reuses the already validated full-test probabilities for the non-ABCD-filtered event view instead of running the filtered prediction a second time. The SR score axes are detected from the CSV `{axis}_low` / `{axis}_high` columns so qcd_est can consume either the legacy first `NUM_CLASSES − 1` axes or all class-score axes. It defines `A` as the union of those score bins with all configured ABCD branches passing their `selection.json` thresholds, `B` as outside that union with all configured ABCD branches passing, `C` as inside that union with all configured ABCD branches failing, and `D` as outside that union with all configured ABCD branches failing; events where only some configured ABCD branches pass are excluded from A/B/C/D. QCD classes are identified by `class_groups` names containing `qcd` case-insensitively, and all samples from those classes are summed for the ABCD `A/B/C/D` totals, `qcd_true`, `qcd_predict`, and `total_predict`; the per-class `groups/*` outputs remain the MC-true class yields. A single QCD ABCD scale from the union-level `B/C/D` totals is then applied to all individual signal regions, after the optional per-tree `qcd_predict_scale_multipliers` factor is applied; qcd_est logs the raw ABCD prediction, raw scale, manual multiplier, final scale, and per-SR raw/scaled QCD predictions for debugging. The validation plots keep the finite-MC / ABCD-propagated uncertainties based on `sum(w^2)` and the B/C/D propagation; `qcd_abcd_region_counts.pdf` and `qcd_abcd_region_fractions.pdf` stack the configured `class_groups` classes with the shared fixed class palette and generated extra colors if needed, while `qcd_abcd_region_counts_linear.pdf` saves the same counts with a linear y axis. The QCD-merged summaries (`qcd_abcd_region_counts_qcd_merged.pdf`, `qcd_abcd_region_counts_qcd_merged_linear.pdf`, and `qcd_abcd_region_fractions_qcd_merged.pdf`) combine every `class_groups` class whose name contains `qcd` case-insensitively into one `QCD` stack color and legend entry, leaving non-QCD classes unchanged. Optional per-tree `a_region_shape_branches` entries produce normalized branch-shape PDFs under `output_dir/a_region_shapes/`; for each configured branch, qcd_est writes one class-overlaid, unit-area weighted histogram for every signal bin plus one for the full A-union, without applying ABCD prediction scaling, and drops values `<= -10` before binning/normalization so missing-slot values such as `-99` do not set the visible range. The ROOT output is combine-facing: it writes `metadata/signal_regions` with the selected `bin_index` values, and every saved category (`samples/*`, `groups/*`, `qcd_predict`, `qcd_true`, `total_predict`, and `total_true`) stores each SR as one-bin histograms under `sr{bin_index}/yield`, `sr{bin_index}/stat_error`, `sr{bin_index}/scale_error`, and `sr{bin_index}/n_entries` (raw MC event count), plus a category-level `covariance_total` TH2 and a one-bin `mean_event_weight` (the category's typical per-event weight, the median |w|, over all selected events with every ABCD branch passing, at any score; until 2026-10-06 the mean, which for QCD is dominated by a few very heavy low-HT events: boosted3 mean 153 vs median 28.5 events-worth; the name is kept for combine). `stat_error` is the finite-MC uncertainty `sqrt(sum w^2)` and `covariance_total` is `diag(sum w^2)` for the MC-true categories; for `qcd_predict`, `stat_error` is the MC statistics of the per-SR `A_i/A` shape fraction, `scale_error` the B/C/D-propagated ABCD scale uncertainty, and `covariance_total` their sum (diagonal fraction term plus the fully correlated scale term), with `n_entries` the QCD MC counts in each `A_i` and `mean_event_weight = scale × typical (median |w|) QCD event weight`. `qcd_predict/abcd_scale` stores the final scale (predicted / MC-true QCD in the A union, i.e. the MC closure) and `qcd_predict/abcd_scale_error` its B/C/D MC-stat uncertainty. Every sample of `class_groups` gets a `samples/*` bundle, with zeros when none of its test events survives the filtering (until 2026-10-07 such samples had no bundle, and combine aborted on a missing signal sample, e.g. in the 2-lepton category). `metadata/sr_csv_hash` (one-bin histogram) holds the first 13 hex digits of the SHA-256 of the SR CSV bytes as an integer (exact in a double); the systematics scripts record the same hash and combine checks them against each other. Negative SR yields are written as 0 with a warning.

`abcd_mode` (default `union` = everything above; `per_sr` added 2026-10-07): with `per_sr` every SR gets its own prediction `A_i = C_i × B/D` instead of the union scale applied to the MC-true QCD shape. `C_i` is the SR box in the control window `abcd_control_window[tree] = [low, high]` (exclusive bounds) of the single ABCD branch inside its fail region, and B / D are the pass region / that control window in the B/D sideband (`abcd_sideband_mode`); for boosted3 the window is the low-mass sideband 0 < `msoftdrop_1` < 50 GeV, because the QCD score tail above the mass window is 1.5–3× harder while the one below it agrees with the window within ~12% (`study_boosted3/abcd_viability.py`). `abcd_per_sr_nonclosure[tree]` (required, a fraction) is passed to combine as the non-closure uncertainty, and `qcd_predict_scale_multipliers` must be 1. `qcd_predict` then holds `C_i^QCD × TF` (MC, TF = QCD B/D; `stat_error` from `C_i`, `scale_error` from TF, fully correlated in `covariance_total`), `abcd_scale` is the MC closure ΣA_pred / ΣA_true (0 with a warning if the A union has no QCD MC), and the file additionally holds `qcd_predict/{per_sr_abcd (= 1), abcd_tf, abcd_tf_error, abcd_nonclosure}`, the control regions in the usual bundle layout under `control/{samples/*, groups/*, qcd_true}` (`sr{bin_index}` = the control region of that SR) and the B and D regions under `abcd_bd/{samples/*, groups/*, qcd_true}` (sub-bins `b`, `d`), each with `mean_event_weight` = the typical (median |w|) event weight in the control window. The ABCD region plots then show C and D in the control window. In `union` mode the output is unchanged.

### CMS combine wrapper
```bash
./run.sh 7
./run.sh 7 combine/config.json
```

`combine/combine.C` wraps CMS `combine` to compute expected significance and expected `AsymptoticLimits` (CLs) from the ROOT output of `qcd_est.py`. It reads [combine/config.json](combine/config.json), which lists one or more channels, each pointing to a `qcd_abcd_yields.root` written by `mode=5` and the matching per-channel `bdt_root` directory written by `train.py`. `combine.C` loads `class_groups` from each channel's `bdt_root/config.json`, resolves that copied config's `sample_config` relative to `selections/BDT` like `qcd_est.py` (the nearest ancestor of `bdt_root` that is `selections/BDT`, so models in study subdirectories work too; else `bdt_root`'s parent), and requires all channel BDT configs to share the same class membership plus signal/QCD definitions before building one shared scenario list. Group names from `class_groups` are matched against `groups/*` in the ROOT file by the same slugified lowercase convention used by `qcd_est.py`, and QCD classes are the class names containing `qcd` case-insensitively. It must be run inside a CMSSW area that has `HiggsAnalysis/CombinedLimit` built, so that `combine` and `combineCards.py` are on `$PATH`.

For every channel it loads the stored yield/covariance bundles from that channel's own SR list (`metadata/signal_regions` when present, otherwise sequential `sr1..srN` for older files): `samples/{sample}/srN/{yield,stat_error,scale_error,n_entries}`, `groups/{group}/srN/{yield,stat_error,scale_error,n_entries}`, `qcd_predict/srN/{yield,stat_error,scale_error,n_entries}`, each bundle's `covariance_total` and `mean_event_weight`, and `qcd_predict/{abcd_scale,abcd_scale_error}`; ROOT files written before the MC-statistics treatment lack these histograms and must be regenerated with `qcd_est.py`. Different channels, such as `fat2` and `fat3`, may have different SR counts; no channel is padded or truncated. It then iterates over scenarios:
- `combined`: signal = the sum of all signal groups from `groups/`; backgrounds = the remaining groups.
- `class`: one row per signal class; signal = that class's `groups/` block; backgrounds = every other group.
- `sample`: one row per signal sample; signal = that sample's `samples/` block; backgrounds = the remaining available sample blocks.

For each scenario combine is run twice: once using the MC-true group/sample yields directly from the ROOT file, once replacing all QCD classes (matched by `class_groups` names containing `qcd` case-insensitively) with the single merged `qcd_predict` yield while keeping the other backgrounds on their MC-true group/sample yields. Every channel is validated before running: all configured groups must exist, every configured signal sample must exist, and the code refuses to regularize, clamp, or synthesize missing/zero-rate inputs. Each SR is its own one-bin shape channel named `<channel>_sr<bin_index>` with templates in `shapes_<channel>.root` (rates and observation `-1`, Asimov `data_obs` = sum of processes; since 2026-10-07 an exactly empty template, e.g. a signal sample without events in an SR, gets rate `0`, because combine keeps rate `-1` for an empty template and then rejects the process in `text2workspace` with "Null norm"). By default (`use_root_covariance=false`) the statistical model is: (1) finite MC statistics through `* autoMCStats 10` (combine's Barlow-Beeston-lite with its default of excluding signal), with template bin errors = the stored `stat_error`; (2) a zero-count floor for floor-eligible processes — every background class process in the `combined`/`class` scenarios and the ABCD `bkg_qcd` prediction in all scenarios, but not individual background samples in `sample` scenarios — in each SR where that process's yield is zero (no MC events, or a signed sum clamped to 0): a `zc_<channel>_sr<id>_<process> gmN 0 α` row with `α` = the process's `mean_event_weight` (since 2026-10-06 the median |w| of its events, see qcd_est), where the template holds `α` with zero error, because in autoMCStats channels the normalisation comes from the template, which the `gmN 0` parameter multiplies (a zero-content template would make combine skip the process); combine initialises a `gmN N` parameter at N + 1, so both combine calls pass `--setParameters rgx{zc_.*}=0` and the floors start at 0 (prefit and in the Asimov dataset) and can only rise in the fits at the cost of their Poisson constraint. Before 2026-10-07 they started at 1, i.e. every floor put its full `α` into the Asimov data while its constraint pulled it to 0, and the fits attributed those events to the signal: on the boosted3 study model (combined scenario, MC-true QCD) Z = 0.90 with an expected limit r < 19.6, which are mutually inconsistent, became Z = 0.29 with r < 5.9 (per-SR ABCD: Z 0.065 → 0.16, r < 11.0 → 10.0). Floor-carrying processes are never dropped as zero-yield; (3) for the ABCD QCD prediction, two per-channel lnN rows correlated across that channel's SRs, `qcd_abcd_stat_<channel>` with `κ = 1 + abcd_scale_error / abcd_scale` and `qcd_abcd_nonclosure_<channel>` with `κ = 1 + |1 − abcd_scale|` (rows with `κ = 1` are omitted). In `enabled_nuisances` (empty = all), these terms are controlled by the names `autoMCStats`, `zero_count_floor`, `qcd_abcd_stat` and `qcd_abcd_nonclosure`. Systematic rows (2026-10-07): every process carries its MC samples (`member_samples`: the class members, the signal classes' members, or the single sample in `sample` scenarios; none for the data-driven ABCD `bkg_qcd`). The theory, pileup, JES and JER ratio of a process in an SR is the mean of its samples' ratios (per-SR entry of the JSON when it has events, else the inclusive one) weighted by the samples' MC yields in that SR from the channel's `samples/` bundles; before, class averages used the raw `nom_sum` of the JSONs (unnormalised `sum(weight_pu)`), fallback entries counted with their inclusive `nom_sum`, `sample`-scenario backgrounds and the MC-true `bkg_qcd` got no theory/pileup/JES/JER and the MC-true QCD no `lumi`, and theory used only the inclusive ratios. Asymmetric lnN entries are written `kdown/kup` (combine's order; before up/down, which inverted pulls and impacts). Theory rows: `theory_pdf`, `theory_ps_isr` and `theory_ps_fsr` correlated across processes, the QCD scale one nuisance per process, `theory_scale_<process>` (correlated across channels; `enabled_nuisances` name `theory_scale`). `lumi` applies to every process with MC samples. `enabled_nuisances` names are validated (unknown name = error). The per-SR ratios must belong to the channel's SRs: an entry with `regions` whose `sr_csv_hash` differs from the channel's `metadata/sr_csv_hash` is an error, and a missing hash on either side gives a warning. If a `sample` scenario's signal process is identically zero in some channels, those channels are skipped with a warning; if the signal sample is identically zero in every channel, the wrapper logs a warning, writes `0` into the significance CSV field and `inf` into the limit CSV fields, and continues with the remaining scenarios. If `AsymptoticLimits` returns successfully but its ROOT output still lacks the expected quantiles, the wrapper logs a warning, keeps the significance and writes `nan` into the limit CSV fields (before 2026-10-07 the significance was overwritten with `0` and the limits set to `inf`). Any other failure of a scenario (combine error, invalid inputs) is logged, stored as `nan` in its CSV rows, and the remaining scenarios still run; the CSVs are always written and the run then exits non-zero (before, the first failure aborted the run without CSVs).

Per-SR ABCD (2026-10-07): for a channel whose ROOT file has `qcd_predict/per_sr_abcd` = 1 (qcd_est `abcd_mode: per_sr`), the ABCD scenarios replace the fixed `qcd_predict` yields by a simultaneous fit of the control regions. A second card per channel, `card_<channel>_abcdcr.txt` with `shapes_<channel>_abcdcr.root`, has one bin per control region `<channel>_cr<bin_index>` plus `<channel>_abcdB` and `<channel>_abcdD`, with the same signal and background processes built from the `control/` and `abcd_bd/` bundles (autoMCStats, zero-count floor and `lumi` as in the SR card, but no theory/pileup/JES/JER rows, whose inputs are per SR), and `bkg_qcd` with fixed templates (zero error) 1 in each `C_i` and the MC QCD yields in B and D, normalised by the free rateParams `qcdC_<channel>_sr<id>` (absolute; start = MC QCD in `C_i`, range `[0, max(10 × Asimov count, 10)]`) and `qcdB_<channel>`, `qcdD_<channel>` (relative to MC, `[0, 10]`). In the SR card `bkg_qcd` holds the MC transfer factor B/D (zero error, no zero-count floor) and the formula rateParam `qcdA_<channel>_sr<id> = qcdC × qcdB / qcdD`, so `A_i = C_i × B/D` with `C_i`, B and D constrained by the (Asimov) control-region counts: the QCD uncertainty in each SR is the Poisson uncertainty of its control-region count, not the QCD MC statistics, and signal contamination of the control regions is part of the fit. The SR card gets `qcd_abcd_nonclosure_<channel>` with `κ = 1 + abcd_nonclosure` and no `qcd_abcd_stat` row. The control card's Asimov data is the sum of its processes (QCD at its MC yields). Channels without the marker keep the union treatment.

When `use_root_covariance=true`, autoMCStats and the zero-count floor are not written and template bin errors are 0; instead each process's `covariance_total` (which now carries `sum(w^2)` and, for `qcd_predict`, the ABCD scale correlation) is eigen-decomposed and every retained eigenmode (eigenvalue `> eigen_rel_cutoff × max(diag(cov))`) becomes one Gaussian shape nuisance. The templates start from `Up_i = rate_i + √λ_k · V_{i,k}` and `Down_i = rate_i − √λ_k · V_{i,k}`; if that would make any bin or whole-template norm non-positive and `rescale_shape_modes_to_positive=true`, the wrapper instead writes `Up_i = rate_i + a·√λ_k · V_{i,k}` and `Down_i = rate_i − a·√λ_k · V_{i,k}` with the largest safe `a < 1`, then compensates in the datacard with a `shape` coefficient of `1/a`. This optional mode represents the process-yield covariance as Gaussian shape nuisances instead of autoMCStats. Per-channel datacards and shape ROOT files are written under `output_dir/work/<qcd_mode>_<scope>_<name>/` for the all-channel run and under `output_dir/work/channel_<channel>_<qcd_mode>_<scope>_<name>/` for single-channel reruns. `combine` is then invoked as `-M Significance -t -1 --expectSignal 1` and `-M AsymptoticLimits -t -1 --run expected`, and the resulting `higgsCombine*.root` files are parsed to fill four all-channel CSVs in `output_dir`: `significance.csv`, `limits.csv`, `significance_abcd_mc.csv`, and `limits_abcd_mc.csv`. It also reruns the same scenarios for each configured channel individually and writes `significance_by_channel.csv`, `limits_by_channel.csv`, `significance_by_channel_abcd_mc.csv`, and `limits_by_channel_abcd_mc.csv` with an extra `channel` column. The MC-true and ABCD CSVs share the same row order within their all-channel and per-channel groups. When `keep_work: true` (default) the generated datacards, shape ROOT files, and combine outputs are left in place for inspection; with `keep_work: false` the work directory is removed after the final CSV is written.

### Jet energy corrections and JES/JER systematics

`selections/convert/convert_branch.C` currently applies no jet energy correction: the experimental scouting-to-offline correction (`JetPtCorrector`, the convert config's `jet_pt_correction` block, `scoutingPUPPI_corrections.json.gz`, and correctionlib detection in `run.py`'s `compile_binary()`) was removed on 2026-10-01; proper JECs will be added later. `loadAppConfig()` throws if a convert config still contains a `jet_pt_correction` block, so the leftover `selections/convert/config_{jes,jer}_{up,down}.json` variation configs fail instead of silently writing nominal copies. Data converted with the removed correction (e.g. `data_2024` converted 2026-09-25) is not consistent with the nominal MC and must be reconverted. Until a JEC implementation with JES/JER variations exists again, the shifted converted-ntuple sets needed by the scripts below cannot be produced; the scripts, `run.py` modes 11/12 and combine's optional JES/JER nuisances stay in place for that implementation.

`selections/jes_syst/jes_syst.py` / `selections/jer_syst/jer_syst.py` compute JES/JER shape-systematic yield ratios per MC sample, per tree, per signal region — analogous in output shape to `pileup_syst.py`'s `pu_up`/`pu_down`, but structurally different in how the ratio is built: a JES/JER shift changes jet kinematics (and therefore every pt/mass-derived BDT feature), so "up"/"down" cannot be an alternate weight column of the same tree the way pileup/theory variations are. Instead each script reads three *independent* converted-ntuple sets for the same sample — nominal (`input_root`), and the `jes_up`/`jes_down` or `jer_up`/`jer_down` shifted sets (`input_root_up` / `input_root_down` in `selections/{jes_syst,jer_syst}/config.json`) — scores each independently with the tree's trained BDT, buckets events into the same score-box + msoftdrop-window signal regions as `qcd_est.py`, and takes `jes_up = sum(weight_branch on jes_up tree) / sum(weight_branch on nominal tree)` (and the down/jer equivalents). The shared context-building, feature-standardization, and region-masking code lives in `selections/jet_syst_common/jet_variation_common.py` (mirrors `pileup_syst.py`'s `_build_tree_context`/`_infer_proba`/`_region_mask` closely enough that a change to the SR-bucketing convention in one place should be mirrored in the other). `weight_branch` (default `weight_pu`) is the per-event weight summed on each side of the ratio; both scripts support the same `submit_samples` per-sample SLURM-sharding config key as `pileup_syst.py`/`theory_syst.py`. Outputs: `jes_syst_yields.{json,csv}` / `jer_syst_yields.{json,csv}` in each script's `output_dir`, with a `nom_sum` field per entry (inclusive and per-region) so `combine.C` can compute the same nom_sum-weighted per-class average it already does for pileup.

`combine/combine.C` reads `jes_syst_json` / `jer_syst_json` (optional config keys, parallel to `theory_syst_json`/`pileup_syst_json`) into `cfg.jes_fracs` / `cfg.jer_fracs` (`JesFracs`/`JerFracs`, structurally identical to `PileupFracs`: an inclusive ratio plus per-SR ratios keyed by `bin_index`, falling back to inclusive when a per-SR entry is absent or has `nom_sum <= 0`). `writeJesLnN`/`writeJerLnN` (nuisance names `jes` and `jer`) use the same yield-weighted per-SR row writer as theory and pileup (`writeRatioLnN`, see the combine section) and are called from `writeChannelDatacard` alongside `writeTheoryLnN`/`writePuLnN`. Each JSON entry with `regions` records the `sr_csv_hash` of the SR CSV it used (theory_syst.py, pileup_syst.py and, through jet_variation_common.py, jes_syst.py / jer_syst.py), which combine checks against the qcd_est output. As with `theory_syst_json`/`pileup_syst_json`, a missing/absent `jes_syst_json`/`jer_syst_json` path is a warning, not an error — the corresponding nuisance is simply omitted from datacards until the JSON exists.

`plotting/sr_sensitivity.py` reads [plotting/config_sr_sensitivity.json](plotting/config_sr_sensitivity.json) and writes to its `output_root` (default `plotting/sr_sensitivity/`). It imports `background_estimation/qcd_est.py` as a module once per referenced qcd_est config (setting `QCD_EST_CONFIG_PATH` before import) and reuses its test-split loader, weights, model inference, thresholds, and SR-box definitions; it does not run the qcd_est prediction-reference validation, and it sets the imported module's `INFERENCE_THREADS` to the CPUs actually allocated (`os.sched_getaffinity`) so XGBoost does not oversubscribe a SLURM allocation. (1) `summary_categories`: reads `groups/{class}/sr{N}/yield` from each config's qcd_est ROOT output and writes `sr_yield_summary.pdf` (stacked MC yields per SR over all categories, per-SR Asimov Z in the lower panel; combined `sqrt(sum Z^2)` is logged). (2) `targets`: for each `{qcd_est_config, bin_index, variables, signal_line_scale}` it selects the qcd_est A-region events of that SR (score box + all `selection.json` thresholds, including the ABCD msoftdrop window), cross-checks per-class yields against the qcd_est ROOT file (logged `OK`/`MISMATCH`), and writes `{output_root}/{tree}_sr{N}/{variable}.pdf` stacked MC histograms (signal classes stacked on top, MC-stat hatched band, optional dashed signal×scale line, lower panel per-bin S/√B). Variables that are themselves cut on (threshold branches, or `score_{class}` for SR score axes) are drawn N-1 with dotted cut lines. Binning/labels come from the config's `variables` map; under/overflow is folded into the edge bins and values `<= -990` are dropped per variable. The SR label and S/B/Z are shown as the legend title. (3) Optional `data_overlay` (`sample`, inclusive `blind_window`, and per-variable `plots` entries with `drop_cuts`, `blind`, optional `note`) adds blinded data to the listed variables only, as separate `{variable}_data.pdf` files next to the MC-only PDFs. The selection is the SR (score box + thresholds) minus `drop_cuts`; data events with any `blind` branch inside `blind_window` are removed before histogramming, while MC uses the same selection but leaves the plotted variable's own window unblinded. The total MC stack (and its stat. band) is scaled to the data integral in the plotted variable's sideband bins (bins outside the window; the bin edges must include the window edges), the legend title shows that scale, the blinded range is shaded, and the lower panel shows Data/MC in the sidebands. The checked-in config blinds 50–150 GeV: the `msoftdrop_1` plot drops only its own cut and blinds `msoftdrop_1`; the `msoftdrop_2` plot drops both mass cuts and blinds events with either jet in the window. Data histograms come from `python3 plotting/sr_sensitivity.py --data-file K` (SLURM array `plotting/submit_sr_sensitivity_data.sbatch`, one task per sorted `{sample}_*.root` data file found via the copied BDT `input_root`/`input_pattern` with `{sample_group}_mixed` → `{sample_group}`): each task applies the thresholds not dropped by any data plot before BDT inference, fills the blinded histograms, and writes only those histograms to `{output_root}/data_hists/{tree}_sr{N}/{K}.npz` (with the source file path). The plotting run requires one histogram per data file and fails otherwise.

`signal_region_hist.py` option `zero_count_floor` (scan config, default `false`; added 2026-10-06): in a candidate region where a background class has no MC events (or a non-positive weighted sum), that class's typical event weight `α` (median |w|) over all scan events (the analogue of qcd_est's `mean_event_weight`) is added in quadrature to `σ_B` in the Asimov Z — the optimiser's version of combine's zero-count floor `gmN 0 α`. It is applied in the interval sweeps (per-class count/weight histograms), in the exact per-box evaluation and in the reported per-SR `Z`; with the option off the scan is unchanged. Motivation: in boosted3 every QCD MC event weighs 10–32 events-worth on the eval/test splits, and the eval-optimised SRs (with or without `min_bkg_entries` or a larger `min_bkg_weight`) contained no QCD event at all on eval but 1–11 on test, i.e. the optimiser picked regions that are QCD-free only by chance. With the class mean as `α` (first trial) the QCD floor was 90 events-worth on eval, so the optimiser chose regions with exactly one QCD event of ~25 instead (test: 4, 1, 13, 1 QCD events); hence the median.

`background_estimation/submit_sr_qcd_est.sbatch <category>` runs `selections/signal_region/signal_region_hist.py config_hist_<category>.json` followed by `background_estimation/qcd_est.py` with `config_<category>.json` for one analysis category in a single SLURM job (qcd_est only runs if the SR scan succeeds); submit it once per category and chain `plotting/submit_sr_sensitivity.sbatch` with `--dependency=afterok:...` so the summary reads refreshed qcd_est ROOT files.

`plotting/data_mc.py` reads [plotting/config.json](plotting/config.json) and [plotting/branch.json](plotting/branch.json) and works in two stages per tree in `submit_trees` (restructured 2026-10-07): a fill stage that reads every input file once and stores all histograms, and a plot stage that renders them without reading the inputs. `python3 plotting/data_mc.py` runs both, `--fill-only` / `--plot-only` (alias `--restyle`) one of them; the old `--save-hists` / `--use-cached-ranges` are gone (the histogram file replaces both). `class_shapes.py` still imports the older streaming helpers (`_prepass`, `_stream_hists`, `_resolve_binning`, …), which are kept.
- Configs: the BDT-tree copies of `config.json` (`class_groups`, `input_root`, `input_pattern`, `model_pattern`), `branch.json` (model inputs), `selection.json` (`clip_ranges`, `thresholds`, `log_transform`) and the model from `bdt_root` with `{tree_name}` substituted; `input_root` relative to the BDT script directory (parent of `bdt_root`). `class_groups` / `mc_samples` overrides of the plotting config work as before.
- Branches: the `onlyMC: false` outputs of the tree in `selections/convert/branch.json` (slots expanded, minus `skip_branches`, optionally restricted by `plot_branches`), plus one `score_{class}` per model class when the tree has model input branches (`branch.json` of `bdt_root`).
- MC events: every entry of every file, so the MC is normalised to its full sample (a first version of 2026-10-07 read only the entries after the training range, which the user rejected because the Data/MC normalisation needs all MC events); the BDT scores of the training events are therefore biased by the training, which affects the MC `score_*` histograms. Weight `raw_w × g × target_total / (N_tree × <raw_w>_all)` with `target_total = lumi_total × xsection × N_tree / raw_entries`, `raw_w` the product of the plotting config's `event_reweight_branches[tree]`, `g` the signed generator-weight factor (see "Generator weights and event-weight normalisation"). Data: every entry, weight 1, `{sample_group}_mixed` rewritten to `{sample_group}`. `lumi_total` is the sum of the `lumi` of `data_samples` in `src/sample.json`.
- Fill stage: one `multiprocessing` task per input file (entry range), the model loaded once per worker with one XGBoost thread. Per chunk: weights, model scores (clip/log standardisation, decorrelated features dropped), plot selection = `selection.json` thresholds (none with `--no-selection`) plus `plot_thresholds[tree]`, then **blinding** (default): every data event inside a signal region — any score box of `signal_region_csv[tree]` (same half-open boxes as qcd_est) and all `selection.json` thresholds, i.e. qcd_est's A region — is removed; MC is never blinded (a first version also removed the MC events, changed at the user's request), so in bins with signal-region events the MC exceeds the data by their MC yield. `--unblind` keeps the data events. A tree without signal regions (control regions) must be listed in `unblinded_trees`; a tree to be blinded without a model or SR CSV is an error. Then clip ranges, and every branch is filled on a fine grid of `hist_refine` (default 10) × its plot bins plus under/overflow: range from the `plotting/branch.json` `x_range`, `[0, 1]` for scores, else the min/max of a scan of the first `range_scan_entries` (default 200000) entries of every sample; sentinels (`< -990`) and, for log-x branches, non-positive values are dropped per branch. Theory-weight samples (`has_theory_weights`) also fill the per-member histograms (PDF, α_s, scale, PS) in the same pass. Output: `{output_root}/{tree}_hists.npz` (per branch the fine edges, per-class MC sum w / sum w², data, theory members; `meta` with the classes, branches, log-x flags, blinded flag, SR CSV and its hash, per-sample read/selected/blinded counts, the flat theory fractions). Checked 2026-10-07 on pseudo-data (the `www` files read as data): blinded = 80 of 7491 selected events, identical to qcd_est's SR boxes and thresholds; stored data histograms sum to the 7411 kept events; `--unblind` keeps 7491; the `www` MC (same files) keeps all 7491.
- Plot stage: rebins the fine histograms (under/overflow folded into the edge bins): without an `x_range` override, the populated fine bins are grouped into about `bins` bins on the fine edges (exact); with an override (or for scores), the fine bins are mapped by their centres, exact when the edges lie on the fine grid (a warning otherwise: refill for exact bins). Overrides `bins`, `x_range`, `y_range`, `logx`, `logy` from `plotting/branch.json`; `logy` on by default. The theory band comes from the rebinned member histograms (`_theory_shape_band`), else the flat per-class fractions. Blinded plots carry the note "Data in signal regions removed".
- Output PDFs as before: `{output_root}/{tree_name}_{branch}.pdf` (stacked MC, data, MC-stat and theory bands, Data/MC ratio) and `{tree_name}_{branch}_normal.pdf` (MC total and data each scaled to unit area, `A.U.`).

## Configuration Architecture

All tools are driven by JSON config files. Sample definitions live centrally in [src/sample.json](src/sample.json); individual tool configs reference it via the `sample_config` key.

- **[src/sample.json](src/sample.json)** — master sample registry. Each entry has `name`, `path` (DAS path, string or list), `sample_ID`, `is_MC`, `is_signal`, `xsection`, `lumi`, and `raw_entries`, plus `genweight_mean` for MC (mean signed generator weight, written by `convert_branch <sample> --update-genweight-mean` and required by every MC weight builder). `convert_branch.C` updates `raw_entries` for the running sample once after the final input batch, using the chosen `tree_name` entry total accumulated across all ROOT files resolved from that sample's configured `path` values.
- **[selections/convert/config.json](selections/convert/config.json)** — controls convert step: output paths, thread count, file size limits, pileup weight CSV path pattern.
- **[selections/mix/config.json](selections/mix/config.json)** — controls the optional mix step: selected trees, input/output ROOT roots and patterns, sample config, thread count (used for the OpenMP input-chunk scan), deterministic `random_state`, and the block-size bounds `min_block_entries` / `max_block_entries` (defaults `32` / `4096`) used for per-tree block shuffling while preserving chunk layout.
- **[selections/convert/selection.json](selections/convert/selection.json)** — physics selection: event preselection string, per-collection cuts/sorts, and `tree_selection` that splits output into the production trees (older docs below still say `fat2`/`fat3`): `boosted3` (≥3 AK8 jets, all with the ISR-rejection score > 0.469, no veto lepton), `boosted2_resolved` / `boosted2_unresolved` (2 AK8 jets, or ≥3 failing that score, no veto lepton, ≥2 / <2 `ak4_resolved` jets), `boosted2_leptonic_1lep` (≥2 AK8 jets, exactly one `lep_veto` lepton) and `boosted2_leptonic_2lep` (≥2 AK8 jets, an SFOS `lep_veto` pair); the categories are mutually exclusive, and ≥2-lepton events without an SFOS pair are in none. The AK8 collections `ak8` and `ak8_kept2` require `pT > 175 GeV` and `|η| < 2.5`. Selections are parsed and compiled by the C++ expression engine.
- **[src/simple_json.h](src/simple_json.h)** — the JSON parser used by the C++ tools; for duplicate object keys the last value wins, as in Python's `json`.
- **[selections/convert/branch.json](selections/convert/branch.json)** — declares all input NanoAOD branches to read (scalars and collections with p4 definitions) and output branches to write.
- **[selections/weight/config.json](selections/weight/config.json)** — pileup reweighting settings: data pileup histogram files (nominal/low/high for systematics). The checked-in files are the full-year 2024CDEFGHI golden profiles, while the analysed data is 2024G/H/I: build the matching profiles with [selections/weight/make_data_pileup.sh](selections/weight/make_data_pileup.sh) (run on lxplus with `pileupCalc.py` from the processed-lumi JSON written by the data merge and the BRIL pileup JSON), point `pileup_data_files` at them, rerun mode 1 and reconvert the MC. `weight.C` writes weight 0 in bins without MC events and warns with the data probability lost there. In `convert_branch.C`, a `Pileup_nTrueInt` outside the weight CSV range gets weight 0 (previously 1).
- **[selections/BDT/config.json](selections/BDT/config.json)** — controls model training inputs and outputs: `submit_trees`, `input_root`, `input_pattern`, `class_groups`, `output_root`, `model_pattern`, top-level `model_type` (`bdt` or `nn`, defaulting to `bdt`), `entries_per_sample`, `train_events_per_class`, `eval_events_per_class` (default `test_events_per_class`) and `test_events_per_class` (per-class budgets of the three splits, 0 = off; see "Model Training Details"), `eval_entries_per_sample`, `test_entries_per_sample`, `train_fraction`, `eval_fraction` (see "Train / eval / test split"; production 0.6 / 0.2), top-level `decor_loss_mode` (`smooth_cvm` by default, or legacy `cvm` for BDT), `decor_lambda`, `decor_n_bins`, `decor_n_thresholds`, `decor_score_tau`, `decor_bin_tau_scale`, `decor_msoftdrop_training_max` (positive upper edge for the loose `(0, max)` training window used only when a decorrelate branch named `ScoutingFatPFJetRecluster_msoftdrop_*` also has a `selection.json` threshold), `decor_eff_normalize` / `decor_eff_norm_floor` (efficiency-normalised smooth-CvM, see the BDT/NN training section; default off / 1e-3), and per-tree BDT hyperparameters (`n_estimators`, `n_estimators_decorr`, `max_depth`, `learning_rate`, `learning_rate_decorr`, optional `min_learning_rate` / `lr_reduce_patience`, `gamma`, `reg_lambda`, `reg_alpha`, `min_child_weight`, `subsample`, `colsample_bytree`, optional `colsample_bynode`, `early_stopping_rounds` with default 10) plus `decorrelate`, `decor_efficiencies` (fractions in `(0, 1]` for the decorrelation shape diagnostics), `event_reweight_branches` (list of per-event reweight branches multiplied together before sample normalisation; default `["weight_pu"]`), and `qcd_ht_training_weight_step` (per-tree additive QCD HT training-weight step; `0.10` gives scales `1.0`, `1.1`, `1.2`, ... in increasing configured QCD HT sample order and affects only `train.py`'s internal training/evaluation weights, not saved physics reference weights), plus the per-tree `training_sample_weight_scales`, `training_weight_cap` and `class_balance_power` (see "Model Training Details"). In NN mode, `{tree}_nn` blocks (`fat2_nn`, `fat3_nn`) provide PyTorch MLP hyperparameters: `epochs`, `epochs_decorr`, `hidden_layers`, `activation`, `dropout`, `batch_norm`, `batch_size` (total events per class-balanced mini-batch), `learning_rate`, `learning_rate_decorr`, optional `min_learning_rate` / `lr_reduce_patience`, `weight_decay`, `early_stopping_rounds`, and `permutation_importance_events`; the checked-in NN blocks use `learning_rate: 0.001`, `learning_rate_decorr: 0.0005`, `min_learning_rate: 0.00002`, and `batch_norm: false` so weighted-event training is not coupled to unweighted BatchNorm running statistics.
- **[selections/signal_region/config.json](selections/signal_region/config.json)** — controls signal_region.py: `lumi` (fb⁻¹), `N` / `n_signal_regions` (number of signal regions), `bdt_root` (trained tree output directory to read from, relative to `signal_region/`), `output_dir` (directory for saved PDFs and `signal_region.csv`, relative to `signal_region/`, defaulting to `bdt_root`), `score_axes` (`independent` / first `NUM_CLASSES − 1`, `all`, or an explicit list of class names/indices), `min_bkg_weight` / `min_signal_weight` (minimum weighted yields per region), optional `min_signal_entries` / `min_bkg_entries` event-count minima (in `signal_region_hist.py` the fine refinement of the selected regions also enforces them since 2026-10-06; before, it could shrink a region below the minima, e.g. to 13 background MC events with `min_bkg_entries` 50; with a minimum set, every candidate is recounted per event instead of taken from the interval histograms, which makes the scan ~13× slower), `max_edge_candidates_per_axis` (maximum distinct edges per score axis, including `0.0` and `1.0`), candidate-generation controls `beam_width`, `top_intervals_per_axis`, `coordinate_rounds`, `seed_intervals_per_axis`, `multi_axis_seed_max_axes`, `multi_axis_seed_max_seeds`, `compatibility_seed_anchors`, `compatibility_seed_rounds`, `local_refine_rounds`, `local_refine_neighbor_edges`, `local_refine_top_candidates`, `local_refine_diverse_masks`, and `local_refine_candidate_overscan` (`0` scans the full pre-refinement pool), global-selection controls `global_beam_width`, `branch_bound_max_nodes` (`0` for no node cap), `branch_bound_time_limit_seconds` (`0` for no time cap), `deduplicate_event_masks`, `require_exact_n_regions`, `max_threads`, `progress_every_seconds`, and `seed_quantiles`. There is no candidate-pool or global-candidate count limit in the checked-in scan path.
- **[background_estimation/config.json](background_estimation/config.json)** — controls qcd_est.py: `lumi` (fb⁻¹), `bdt_root` (trained tree output directory to read from), `signal_region_csv` (path to the `signal_region.csv` written by `signal_region.py`), `output_dir` (directory for PDFs and ROOT outputs), `root_file_name` (summary ROOT filename), required per-tree `abcd_branches` (for example `{"fat2": ["ScoutingFatPFJetRecluster_sphere_mass"], "fat3": ["ScoutingFatPFJetRecluster_sphere_mass"]}`) whose entries must exist in the copied BDT `selection.json` thresholds, `abcd_sideband_mode` / `abcd_sideband_width`, `abcd_mode` (`union` / `per_sr`) with the per-tree `abcd_control_window` and `abcd_per_sr_nonclosure` of the `per_sr` mode (see "QCD ABCD estimation"), and optional per-tree `a_region_shape_branches` entries for normalized per-class branch-shape plots in each signal bin and the A-union.
- **[plotting/config.json](plotting/config.json)** — controls data_mc.py: `submit_trees`, `sample_config`, `convert_branch_config`, `bdt_root` (per-tree path pattern, points at the BDT tree output dir that already contains the model and the copied `config.json` / `branch.json` / `selection.json`), `output_root` (per-tree output dir pattern; also holds `{tree}_hists.npz`), `data_samples` (list of data sample names whose entries must exist in `src/sample.json`; data reads are not capped and mixed patterns are rewritten to the non-mixed `data` directory), `signal_region_csv` (per-tree pattern or dict, the SRs removed by the blinding), `unblinded_trees` (trees without signal regions, e.g. control regions), `hist_refine` (fine bins per plot bin, default 10), `range_scan_entries` (entries per sample of the range scan, default 200000), `default_bins` (default histogram bin count), and `event_reweight_branches` (per-tree dict `{tree_name: [branch, ...]}` of reweight branches multiplied into each MC event's weight; default `{"fat2": ["weight_pu"], "fat3": ["weight_pu"]}`; data samples are unaffected).
- **[plotting/branch.json](plotting/branch.json)** — plotting config split by tree (`fat2` / `fat3`). Each tree can define `skip_branches` and a `branches` map. ## Model Training Details

- `selections/BDT/train.py` only trains on the samples explicitly listed in `class_groups`.
- The number of classes is inferred dynamically from `class_groups`; no fixed 5-class assumption is baked into training.
- A class is treated as `single` for plotting if every sample in that class has `is_signal=true`; otherwise it is treated as `background`.
- For each sample, the code first counts all entries across all matched ROOT files in the chosen tree, then defines a fixed sequential split: the first `train_fraction` goes to training, the next `eval_fraction` (if > 0) to the eval split, and the remaining tail to testing. The split is defined on the concatenated sample entry order across files, so `test_ranges.json` can be used later to recover the exact eval and test subsets.
- In `train.py`, `entries_per_sample`, `eval_entries_per_sample` and `test_entries_per_sample` cap how many events are actually loaded from the training, eval and test ranges of that fixed split (each from the start of its range); for the large QCD/V+jets samples most events are therefore never read.
- With `train_events_per_class > 0` (added 2026-10-05; production configs 3,000,000) the training range is read through a per-class event budget instead of `entries_per_sample`: the budget (entries before thresholds) is shared among the class's samples in proportion to their physics totals `xsection × N_tree / raw_entries × training-weight scale` (water-filling: a sample is limited to its training range and the remainder goes to the others), every sample gets at least one block, and each sample reads random whole blocks of 8192 entries of its training range (seeded by `random_state` and the tree/sample name; adjacent blocks merged; a class can exceed the budget by up to one block per sample). The production inputs are not mixed, so the blocks also spread the training events over the input files. The usual `target_total / N_loaded` normalisation keeps every sample's total weight, so the per-event weights inside a class come out roughly equal, which maximises the effective sample size for a given event count. On the 2026-10-02 ntuples this halves the training rows (boosted3 18.9M → 9.7M, boosted2_unresolved 30.9M → 14.6M) and raises the pre-threshold ESS of Top by up to 2× and of VJets by up to 1.7× (except boosted3 VJets, −15% with a quarter of the events); the signal classes and VV are read completely either way, and QCD's ESS is unchanged because its low-HT samples were already read completely (that is addressed by `training_weight_cap` / `training_sample_weight_scales`). `test_ranges.json` records only the train range, not the selected training blocks; no downstream script reads the training events.
- `eval_events_per_class` / `test_events_per_class > 0` (added 2026-10-05; `eval_events_per_class` defaults to `test_events_per_class`; production configs 3,000,000 each on 2026-10-05, set back to 0 = per-sample caps on 2026-10-06, see the end of this item) read the eval / test range the same way instead of `eval_entries_per_sample` / `test_entries_per_sample`, but share the budget in proportion to the physics totals without the training-weight scales (`qcd_ht_training_weight_step`, `training_sample_weight_scales`), so the eval and test events do not depend on the training weights and every study variant reads the same ones; the block seeds include the split name. The selected blocks are the stored `eval_segments` / `test_segments`, and each sample entry in `test_ranges.json` also gets `eval_random_blocks` / `test_random_blocks` (`n_entries`, `block_entries`, `seed`) so `signal_region.py` can repeat the selection when it rebuilds a stale split. `qcd_est.py`, `plotting/data_mc.py` and `signal_region.py` loop over the stored segments and normalise with the number of loaded events, so they needed no change. On the 2026-10-02 ntuples the test split shrinks (boosted2_unresolved 16.8M → 11.0M rows, boosted3 10.4M → 7.3M) while the pre-threshold ESS rises for Top (boosted2_unresolved 1.29M → 3.04M) and VJets (1.61M → 2.82M); QCD again does not change. Reading the full test split instead would have been 168M rows for boosted2_unresolved, too much for qcd_est and the reference files. Checked on the toy: with all budgets 0 the models, references and `test_ranges.json` are bitwise identical to before, the training-only budget gives the same output as before this extension, `signal_region_hist.py` (eval) and `qcd_est.py` (test) validate against the references of a fully budgeted model, and the stale-split rebuild reproduces the stored segments (also on ~600 synthetic multi-file cases). Why the production eval/test budgets went back to 0 (2026-10-06): the weight-share allocation maximises the class-wide effective sample size, but the background events that end up in the SRs are the high-HT QCD tail, whose samples get few events and therefore heavy per-event weights. Test-split weight per event (pre-threshold, 255.8 fb⁻¹) with the 500k per-sample cap / the 3M class budget: boosted2_unresolved `qcd_ht1000to1200` 288 / 3402, `qcd_ht1200to1500` 124 / 3402, `qcd_ht1500to2000` 40 / 2461; boosted3 `qcd_ht1500to2000` 10 / 23, `qcd_ht2000` 2.5 / 23. Such single heavy events dominated the test-split SR backgrounds of the boosted3 study. The training split keeps its budget; the same allocation gives the high-HT QCD samples of the boosted2 trees only ~20k–140k training events (750k with the per-sample cap), which is still to be checked when those trees are retrained.
- Training events are shuffled after loading; test events keep their original order.
- Sample weights are computed separately for the training and test splits, immediately after reading and before any model threshold cuts:
  `target_total       = xsection * tree_entries_total / raw_entries`
  `per_event_weight   = raw_w * g * target_total / (N_loaded × <raw_w>_all)`, with `g = genWeight / genweight_mean` and `<raw_w>_all` the all-generated-event mean of `raw_w` from `src/sample.json` (see "Generator weights and event-weight normalisation")
  where `tree_entries_total` is the total number of entries in the chosen tree across all of that sample's ROOT files (same value for the training and test splits of a given sample), and `raw_w` is the per-event product of the tree's `event_reweight_branches` entries (default `weight_pu`) read on raw values before clip/log/threshold. `N_loaded` is the number of events actually read on that side of the split, so the sample total is `Σ weight = target_total × <raw_w g>_loaded / <raw_w>_all`: the signed selection efficiency relative to the generated sample, including the effect of the pileup reweighting on the selection. With an all-ones `raw_w` and constant positive `genWeight` this reduces to a constant per-event weight. These are the signed physics weights; the training weights are their absolute values rescaled per sample to the same signed total.
- Within each class, the ratio of `target_total` between samples is proportional to `xsection * tree_entries_total / raw_entries`. These per-sample raw weights are frozen before any model threshold cuts, so threshold efficiency changes the post-cut class and sample composition naturally.
- If a per-tree `qcd_ht_training_weight_step` is positive, `train.py` multiplies only its internal `weight` column for samples named like `qcd_ht*` by `1 + rank * step` in increasing HT order (`rank=0` for the lowest configured QCD HT sample). The original `weight_physics` column and all saved prediction-reference weights remain unscaled, and the later class-balancing step still makes each class total equal while preserving the adjusted QCD internal sample proportions.
- A per-tree `training_sample_weight_scales` map `{sample: factor}` multiplies into the same internal training-weight scales (`_training_weight_scales`); a factor `0` removes a sample from the training and early-stopping objective (and from the class-balanced weights of the diagnostic plots) while its physics weights, the prediction references, the SR optimisation and the yields keep it. Samples must be in a class and factors finite and >= 0.
- A per-tree `training_weight_cap` (default `0` = off, otherwise >= 1) limits, after class balancing, every event's weight in the fitted training and monitoring splits to `cap` x the mean training weight of its class, with the class total kept: the weights become `min(s * w, cap * mean)` with `s >= 1` solved so the class sum is unchanged, so the weight cut from very heavy events moves to the rest of the class (sample shares inside the class change). The diagnostic plots and all physics weights stay uncapped. Motivation (boosted3 training view, 2026-10-02 ntuples): the QCD class had an effective sample size of 157 out of 984k events because 75 events of `qcd_ht40to70` … `qcd_ht200to400` (5 of them from `qcd_ht40to70`, with weights up to 2.4e4) carried 23% of the class weight.
- XGBoost uses `min(32, len(os.sched_getaffinity(0)))` threads, i.e. the CPUs of the SLURM allocation rather than the node's core count.
- `BDT_TREES` (comma-separated) restricts a `train.py` run to some of the config's `submit_trees` (unknown names are an error); `python3 run.py 2 <config> --slurm` uses it to submit one SLURM job per tree (`bdt_train_<tree>_%j.out` in `selections/BDT/`; defaults `--slurm-cpus 32 --slurm-mem 200G` for mode 2, `--slurm-time`, `--slurm-account`, `--slurm-partition`, `--slurm-exclude` and `--slurm-extra` as for the other modes), so the trees train in parallel instead of one after another; without `--slurm`, mode 2 still trains all trees locally in sequence.
- Speed of the BDT smooth-CvM decorrelation term (2026-10-05, results bitwise identical, checked on the full loss/gradient/Hessian for several shapes and on a complete toy training: identical models and references): the threshold sigmoids, their derivative and the global efficiency depend only on the class's scores, so `_smooth_cvm_shared_terms` computes them once per class for all decorrelate features; and the two products with the bin memberships use `np.einsum` instead of `@`, because the CMSSW NumPy has no optimized BLAS and its fallback matmul is ~10x slower for these shapes while einsum accumulates in the same order. On a boosted3-like class mix the stage-2 objective is ~2.9x and the metric ~5.6x faster; stage 2 (1000 rounds in boosted3, where the decorrelation loss was still falling) dominates the training time. Threading the per-class loop gave no gain and float32 is not an option: it changes the smooth-CvM loss by ~30% (the loss is a sum of small differences of efficiencies) for a 1.3x gain.
- The production BDT configs use `min_learning_rate` 0.005 (raised from 0.001 on 2026-10-05): with `lr_reduce_patience` 4 the stage-1 learning rate halves 0.05 → 0.025 → 0.0125 → 0.00625 → 0.005 and stage 2 0.02 → 0.01 → 0.005 before ordinary early stopping applies; at the old floor boosted3's stage 1 spent ~660 rounds for a 9.5e-5 relative test-loss gain.
- The reweight branches are loaded alongside the feature branches, consumed solely to build `raw_w`, then dropped from the DataFrame — they never enter model training, standardisation, or threshold filtering. Missing reweight branches in the input ROOT files raise `KeyError`, and a missing `<branch>_mean` in `src/sample.json` (or more than one reweight branch) raises `RuntimeError`.
- Any branch that appears in `selection.json`'s `thresholds` block or in the per-tree `decorrelate` list but is NOT declared in `branch.json` is still read from the ROOT files (alongside the `branch.json` features and the reweight branches) so that `filter_X` can cut on it in the relevant view and the decorrelation step can reference it. After `filter_X`, threshold branches that are not in `decorrelate` are dropped from the DataFrame so the model input feature set remains strictly defined by `branch.json` (decorrelate branches stay in `X` because the training backend separates them into `Z` for decorrelation and trains only on the remaining `branch.json` columns).
- `train.py` builds two threshold views when a configured `decorrelate` branch also appears in `selection.json` thresholds. The training view removes those decorrelate-branch threshold conditions except that any decorrelate branch named `ScoutingFatPFJetRecluster_msoftdrop_*` with a selection threshold is kept with a loose `(0, decor_msoftdrop_training_max)` cut (default 200), and is used for model training, early stopping, decorrelation-loss state, and the training/test class balancing. For `msoftdrop_1`, the ABCD variable of `qcd_est.py`, this window holds 98.5% (boosted3) to 99.8% of the QCD events of the ABCD fail region (measured 2026-10-05 on the 2026-10-02 ntuples; the rest have `msoftdrop_1` > 200 GeV or negative), so it was kept. The full evaluation view reapplies the original decorrelate-branch thresholds on top of the training view and is used for ordinary branch distributions, ROC, score distributions, feature importance, `feature_corr.pdf`, and `test_reference_signal_region.npz`.
- After training-threshold/sentinel filtering, class totals are rescaled separately within the training split, the eval split (if any) and the test split so every class has the same total weight inside that filtered split, with each class total scaled to `N_filtered / N_classes` so the overall XGBoost weight scale stays close to the filtered event count instead of the old large fixed constant. A per-tree `class_balance_power` `p` in `[0, 1]` (default 1 = this full balancing, unchanged code path) instead sets each class total proportional to `(class total of its unbalanced training weights in that filtered split)^(1 − p)` (physics totals up to the per-sample training-weight scales), normalised to `N_filtered` in total; `p = 0` keeps the physics class composition, `p = 0.5` (study variant `balance05`) is partial balancing.
- This post-threshold class balancing preserves the filtered per-sample proportions inside each class for the training-threshold view: each sample keeps the same relative share it had after the fixed pre-cut `raw_w × target_total / Σ raw_w_loaded` weighting and the non-omitted threshold efficiency losses; only the class-level normalisation changes.
- Threshold/sentinel filtering in `filter_X` is applied **only** to branches that appear as keys in the threshold dictionary passed to that call. For each such branch, events with sentinel values (`< -990`) are dropped and the threshold condition is enforced. Branches that are not in that active threshold dictionary are never inspected, so an event with a sentinel value in (for example) a lepton branch is still kept as long as the active threshold view does not target that lepton branch.
- If `decorrelate` is non-empty and `decor_lambda > 0`, `train.py` trains in two stages. In BDT mode, stage 1 uses native `multi:softprob` without decorrelation and stage 2 resumes from the saved stage-1 best model for `n_estimators_decorr` additional rounds with the custom multiclass objective. In NN mode, stage 1 trains a weighted PyTorch MLP with `objective_loss = weighted_CE` on class-balanced mini-batches using sampling-corrected event weights, and stage 2 resumes from the saved stage-1 best MLP for `epochs_decorr` epochs with `objective_loss = weighted_CE + scaled_smooth_CvM_decorrelation` on the same sampler. BDT chooses stage-1 best on test `classification_loss` and stage-2 best on test `total_loss`; NN chooses both stage-local best epochs on epoch-end test `objective_loss`. If decorrelation is disabled, stage 2 is skipped and the stage-1 model is promoted to the main output path.
- In BDT mode, `classification_loss` is the sum-scale weighted softprob loss built from the class-balanced unit-scale training weights (`Σ w·(-log p_true)`), while `mlogloss` is the weighted average of that same quantity (`Σ w·(-log p_true) / Σ w`). BDT stage 1 receives transformed probabilities from XGBoost's builtin objective and BDT stage 2 receives raw margins from the custom objective. In NN mode, `train_objective_loss` and `test_objective_loss` are epoch-end eval-mode full-split batch objectives, not averages of the update-time loss scalars; `backward()` uses the same objective formula on class-balanced mini-batches with sampling-corrected event weights so the balanced sampler still targets the same weighted objective. The component `weighted_ce_loss` is recorded in both stages, and `decorrelation_loss` is non-zero only in stage 2.
- In BDT mode, `regularization_loss` remains a diagnostic quantity and is reconstructed from the current trees in the same native tree-solver parameterization as XGBoost: `gamma` times the number of leaves, plus the `reg_lambda` / `reg_alpha` penalties evaluated on the unshrunk leaf weights (`leaf / eta` for the stage that produced that boosting round). In NN mode, optimizer `weight_decay` is applied through native AdamW decoupled updates and is not represented as a separate logged scalar loss. NN `objective_loss = weighted_CE + decorrelation_loss` with `decorrelation_loss = 0` in stage 1, while BDT keeps the legacy `total_loss = classification_loss + decorrelation_loss` diagnostic.
- When stage 2 is active and both `lr_reduce_patience` and `min_learning_rate` are positive, the stage-2 monitor suppresses early stopping while `eta > min_learning_rate`; after `lr_reduce_patience` consecutive non-improving rounds it halves `eta` (floored at `min_learning_rate`), logs the reduction, resets both stale counters, and only begins enforcing the normal `early_stopping_rounds` threshold once that floor has been reached.
- In the custom-objective decorrelation modes (`smooth_cvm` and `cvm`), the BDT decorrelation term is multiplied by one fixed train-split scale calibrated from the saved stage-1 best model, using `(cls_loss_stage1 + reg_loss_stage1) / max(raw_decor_loss_stage1, ε)`. NN mode supports `smooth_cvm` and calibrates with the stage-1 batch-averaged weighted CE, `cls_loss_stage1 / max(raw_decor_loss_stage1, ε)`, where `raw_decor_loss_stage1` is the same mini-batch smooth-CvM objective used by NN training and epoch-end train/test evaluation. This keeps `decor_lambda` controlling the decorrelation term relative to the same loss definition used by NN `objective_loss`. `smooth_cvm` is the default differentiable mode: it matches the old CvM objective conceptually by comparing score-efficiency curves across decorrelation-variable bins (on QCD events, for the log-odds of every class probability; see the training section), but replaces the hard bin/CDF steps with smooth sigmoid surrogates so the recorded decorrelation loss, objective loss, and training gradient all refer to the same smooth objective. `cvm` keeps the original hard-bin CvM-style loss and its legacy surrogate gradient for backward-compatible BDT studies. Early stopping remains stage-local, using test `classification_loss` for BDT stage 1, test `total_loss` for BDT stage 2, and epoch-end test `objective_loss` for both NN stages.
- `train.py` saves BDT stage-1/final models as `{tree}_model_stage1.json` and `{tree}_model.json`, and NN stage-1/final models as `{tree}_model_stage1.pt` and `{tree}_model.pt`; comparison plots keep `_cls` / `_decorr` suffixes for the stage-1 and stage-2 models respectively. Downstream scripts call the shared `selections/BDT/model_io.py` loader, choose JSON/PKL BDT models or PyTorch `.pt` checkpoints from the copied `model_type`, and apply the multiclass softmax explicitly before using model scores.
- After writing the final model, `train.py` also writes `test_reference_signal_region.npz`, `test_reference_qcd_est.npz`, and `test_reference_qcd_est_full.npz`. Each file stores the exact test-split feature order, sample order, class labels, pre-lumi physics weights, predicted class probabilities, and per-array tolerances for the corresponding downstream preprocessing chain. `test_reference_signal_region.npz` uses the full evaluation thresholds, including original decorrelate-branch thresholds that were omitted or loosened in training, so its stored weights and row set match the downstream signal-region/data-MC score path. `signal_region.py`, `qcd_est.py`, and the derived-score path in `plotting/data_mc.py` multiply the stored reference weights by their local configured luminosity before comparing them to the reconstructed physical weights; any remaining mismatch is treated as fatal and the script exits instead of silently proceeding.
- `background_estimation/qcd_est.py` logs timing and size diagnostics around full-reference validation, including full test-set feature copying, standardisation, model prediction, `.npz` reference loading, label/weight comparisons, and probability comparison. Preserve those logs when editing this path because large QCD test splits can otherwise look stalled after the `Validating full test-set prediction reference` message.
- ROC and score-distribution plots adapt to the configured classes and are written separately for the stage-1 baseline (`*_cls.pdf`) and stage-2 final model (`*_decorr.pdf`) when both stages exist. These ordinary comparison plots use the full evaluation thresholds even when the training objective omitted or loosened a decorrelate-branch threshold. When both signal-like and background-like classes exist, one ROC PDF is written per signal class, overlaying every background class in a distinct color (test curves solid, train curves dashed), and one score PDF is written per signal-background pair. When there is no signal/background split, the code falls back to one ROC PDF per class (treating it as the "signal" against all other classes) and all-pair score distributions.
- After training, `train.py` copies `config.json`, `branch.json`, and `selection.json` into the tree output directory so that `signal_region.py` can run self-contained from that directory.

## Signal Region Scan Details (`signal_region.py`)

- Reads all parameters from `scan.json` (configurable via `SCAN_CONFIG_PATH` env var).
- Loads the optimisation split from `test_ranges.json`: the eval split when the model was trained with one, otherwise the test split (`OPT_SPLIT`; `load_split_data(branches, split)`, with `load_test_data` kept for the purity study scripts). If a frozen file path is stale, that sample's eval or test ranges are rebuilt from the current files with the training-time fractions and caps, or, for a split read through a per-class budget, with the same seeded block choice from its stored `{split}_random_blocks`.
- Physics weights: `target_total = lumi × xsection × total_tree_entries / raw_entries` and `per_event_weight = raw_w × g × target_total / (N_loaded × <raw_w>_all)` with the signed generator-weight factor `g = genWeight / genweight_mean` and the all-event reweight mean `<raw_w>_all` (see "Generator weights and event-weight normalisation"), where `total_tree_entries` is all entries across all ROOT files for that sample in the chosen tree (train + test combined), and `raw_w` is the per-event product of the tree's `event_reweight_branches` in the trained-model config copy (read on raw values, before any clip/log/threshold, and dropped from the DataFrame after `raw_w` is built). The sample total is `Σ weight = target_total × <raw_w g>_loaded / <raw_w>_all`; missing test split files/trees, failed segment reads, non-positive `raw_entries`, or a missing `genweight_mean`/`weight_pu*_mean` raise `RuntimeError`. No class rebalancing is applied.
- Preprocessing (clip, log transform, threshold filter) is identical to train.py's full-threshold evaluation test-split logic.
- Threshold/sentinel filtering matches `train.py`'s downstream evaluation view: only branches that appear in `selection.json`'s `thresholds` block are inspected, including decorrelate branches that may have been omitted from the training objective, and only those branches can drop events for sentinel values (`< -990`) or failed threshold conditions.
- Branch loading mirrors `train.py`: threshold or decorrelate branches that are not in `branch.json` are still read from the test split ROOT files for filtering and decorrelation, then the threshold-only ones (not in `decorrelate`) are dropped from `X` before the existing decorrelation/model-inference step runs.
- Decorrelated features (e.g., `msd8_1`) are excluded from the model input, same as during training.
- Scan dimensions come from `score_axes`: `independent` uses `p(class_0)` through `p(class_{NUM_CLASSES-2})`, while `all` includes every class probability, including the final class so direct upper/lower cuts on that class can be represented.
- Each signal region is a general axis-aligned high-dimensional rectangle: every axis has its own `[low, high)` (`high == 1.0` is open-ended). The previous "single slim slice + other axes open to 1" restriction has been removed; downstream `qcd_est.py` already consumes the per-axis `_low`/`_high` columns from `signal_region.csv`.
- Significance formula per region: the Asimov significance with background uncertainty, `Z = sqrt(2[(S+B) ln((S+B)(B+σ²)/(B²+(S+B)σ²)) − (B²/σ²) ln(1 + σ²S/(B(B+σ²)))])` with `σ² = Σ w²` of the region's background MC (module-level `asimov_z` / `asimov_z_with_error` in `signal_region.py`, shared by `signal_region_hist.py`); it reduces to `sqrt(2[(S+B) ln(1+S/B) − S])` for `σ → 0`. The interval sweeps, candidate evaluation, global selection and the reported per-SR `Z`/`Z_err` (and the per-class `Z` in the report) all use it, so regions whose background rests on few heavy MC events are no longer rated as if `B` were exact. The error on `Z` propagates the MC statistics of `S` and `B` by central finite differences with `σ` held fixed.
- Combined objective: `Z_comb = sqrt(Σ Z_i²)` over the N selected non-overlapping regions. The final selection is global over the generated candidate list rather than sequential: it searches K-region combinations and maximizes `Σ Z_i²`, which is exactly the script's existing combined-significance objective.
- Per-axis edge candidates: total, signal-only, background-only, and unweighted score quantiles are combined with tail-heavy quantiles, capped at `max_edge_candidates_per_axis` distinct edges while always including `0.0` and `1.0`. These edges are the global candidate boundary set.
- Beam coordinate search: seeds include the full box, low/mid/high-tail high-side and low-side single-axis seeds from `seed_quantiles`, and up to `seed_intervals_per_axis` exact single-axis bounded `[low, high)` interval seeds per score axis. `multi_axis_seed_max_axes` / `multi_axis_seed_max_seeds` can add bounded combinations of those one-axis seed intervals so the search starts from simultaneous lower/upper cuts on multiple score axes instead of relying only on later coordinate updates. Optional `forbidden_regions` are still supported for compatibility, but the normal workflow no longer performs one scan per SR. For up to `coordinate_rounds`, every beam state updates every axis by histogramming events that pass the other axes, sweeping all `(a < b)` intervals in `O(K²)`, and keeping the best `top_intervals_per_axis` exact intervals for that axis. Independent per-axis/per-state interval scans may use `max_threads`, but their outputs are merged back into the pool in deterministic scan order so threading does not change the finite candidate set. The beam keeps the strongest states while preserving some non-overlapping diversity, and every valid visited rectangle is added to the candidate pool.
- Compatibility expansion: after the first shared beam pass, the scan takes up to `compatibility_seed_anchors` high-Z anchors chosen by distinct event masks and creates seeds that are guaranteed to be geometrically non-overlapping with each anchor on one separating score axis. It then runs additional coordinate updates while keeping that separating axis fixed, so the pool contains candidates that are explicitly optimized as possible partners for a slightly lower first region. These candidates still enter the same global candidate list; they are not selected greedily.
- Local event-threshold refinement: up to `local_refine_top_candidates` regions are refined for `local_refine_rounds` passes. With `local_refine_diverse_masks=true`, the refinement seed list is chosen by distinct event masks rather than raw Z order, preventing hundreds of geometric variants of the same event set from consuming all refinement passes. Around each current low/high boundary, the scan injects nearby real event score values from the cached per-axis score values (`local_refine_neighbor_edges`) and again performs exact one-axis interval sweeps, adding each valid refined rectangle to the pool.
- Candidate pool: every region is deduped only by rounded `(low, high)` during generation and gated by `B ≥ min_bkg_weight`, `S > min_signal_weight`, and optional event-count minima. No candidate-pool or global-candidate count limit is applied, so candidates are not removed by single-region `Z`. Before global selection, every candidate is shrunk to an event-preserving minimal score box; exact event-mask/canonical-box deduplication then removes only candidates that select the same exact event mask and shrink to the same rounded canonical box. This keeps `S/B/Z` unchanged on the scan events while avoiding deletion of merely lower-ranked but complementary candidates.
- Global selection: `signal_region.py` compiles and loads `openmp_region_select.cpp` into `output_dir/.openmp/` when `max_threads > 1`. The helper first runs a bounded beam search with `global_beam_width` to get a strong incumbent, then runs branch-and-bound over the candidate list with an admissible upper bound that ignores future mutual overlaps but preserves compatibility with already selected regions. Compatibility uses the same exact half-open `[low, high)` interval intersection as the Python event-mask definition; touching boundaries are allowed, but any positive intersection is treated as overlap. `branch_bound_max_nodes=0` disables the node cap, and `branch_bound_time_limit_seconds=0` disables the wall-time cap. If the search completes, the selected set is exact for the finite candidate list; if a cap is hit, the script reports `Z_best`, a conservative `Z_upper_bound`, and the resulting `delta_Z` certificate. If OpenMP build/load fails or `max_threads == 1`, the same search runs in Python. Progress logs report beam rounds, local refinement progress, candidate-pool size, global selector type, completion status, node count, overlap checks, and final `Z_comb`.
- Empty-bin score-axis expansion: after global selection and the non-overlap check, every selected SR is expanded in order (SR1 first, then SR2, …). For each SR, signal-class score axes have their upper bound pushed toward `1.0` and background-class score axes have their lower bound pushed toward `0.0`, but only into space that is empty in MC under that SR's other-axis cuts. Each expansion is constrained so that (a) the SR's exact selected event mask is preserved, and (b) the expanded box remains geometrically non-overlapping with every other selected SR (already-expanded earlier ones and not-yet-expanded later ones). The other expansion direction (signal-axis low / background-axis high) is intentionally **not** expanded. Per-bin `S`, `B`, `Z` are recomputed after expansion and stay numerically identical to the pre-expansion values; only the empty-side score-axis bounds change in the per-SR report and in `signal_region.csv`. The script logs how many signal-axis high bounds and background-axis low bounds were widened.
- Signal class: any class where all member samples have `is_signal=true`. Background: all other classes.
- Output files: `sr_score_*.pdf`, `scores_no_regions.pdf`, `scores.pdf`, `scores_no_regions_radial_equalized.pdf`, `scores_radial_equalized.pdf`, and `signal_region.csv` all go to `output_dir`. The CSV stores one row per selected signal region and expands the high-dimensional bin definition into per-axis `{axis_name}_low` / `{axis_name}_high` columns.

## `run.sh` Behavior

[run.sh](run.sh) supports eight modes:

- `mode=0` compiles `selections/convert/convert_branch.C`, then runs each selected sample as a sequence of bounded batch invocations.
- `mode=1` compiles and runs `selections/weight/weight.C`.
- `mode=2` runs `selections/BDT/train.py` with `BDT_CONFIG_PATH` pointing to the chosen config file.
- `mode=3` runs `selections/signal_region/signal_region.py` with `SCAN_CONFIG_PATH` pointing to the chosen config file.
- `mode=4` runs `plotting/data_mc.py` with `PLOT_CONFIG_PATH` pointing to the chosen config file.
- `mode=5` runs `background_estimation/qcd_est.py` with `QCD_EST_CONFIG_PATH` pointing to the chosen config file.
- `mode=6` compiles and runs `selections/mix/mix.C` with `MIX_CONFIG_PATH` pointing to the chosen config file.
- `mode=7` compiles and runs `combine/combine.C` with `COMBINE_CONFIG_PATH` pointing to the chosen config file. It does not take sample arguments and runs once per invocation.

For `mode=0`, `mode=1`, and `mode=6`, the script resolves the sample list from JSON configs, then runs jobs with `MAX_CONCURRENT_JOBS` parallelism (default 1). For `mode=0`, each per-sample job first runs `convert_branch <sample> --batch-count` with `CONVERT_REFRESH_FILE_LIST=1` (new file-list snapshot; the last stdout line is the count), then runs `convert_branch <sample> <batch_index>` for every zero-based batch index so no convert process reads more than one batch of input files, and merges only if every batch succeeded (otherwise it exits non-zero without merging). The reap helpers succeed when at least one job finished, so the polling loops sleep between checks instead of busy-waiting. `mode=0` with `--slurm` is refused (use `python3 run.py 0 ... --slurm`, which submits one job per batch plus a dependent merge); for the other SLURM modes `--slurm-account` (default `cms-express`) is passed as `sbatch --account` and `--slurm-partition` (default empty) as `--partition`. Log output goes to `selections/convert/log.txt`, `selections/weight/log.txt`, `selections/BDT/log.txt`, `selections/signal_region/log.txt`, `plotting/log.txt`, `background_estimation/log.txt`, `selections/mix/log.txt`, or `combine/log.txt` depending on mode. All eight modes use the same timestamped run-log style in `run.sh`; `mode=0`, `mode=1`, and `mode=6` log per-sample `started` / `finished` records, while `mode=0` also logs per-batch `running sample=... batch=X/Y` records. `mode=2`, `mode=3`, `mode=4`, `mode=5`, and `mode=7` log one `started` / `finished` record for the whole job with an explicit exit `status=`. Inside `selections/BDT/train.py`, `selections/signal_region/signal_region.py`, `plotting/data_mc.py`, and `background_estimation/qcd_est.py`, the script output follows the same concise stage-by-stage `Running ...`, `Wrote ...`, and `Runtime error: ...` style. The compiled binary is removed on exit for the C++ modes. OpenMP is auto-detected for intra-job parallelism when compiling the C++ tools.

`run.py` is the canonical launcher (modes 0–12). Python modes run locally, except mode 2 with `--slurm`, which submits one training job per tree (see "Model Training Details"); `--slurm-cpus` / `--slurm-mem` default to 32 / 200G for mode 2 and 1 / 4G otherwise. Its mode-0 behaviour matches the above: the `--batch-count` call sets `CONVERT_REFRESH_FILE_LIST=1`, a local run merges only when every batch succeeded, and `--slurm` submits one job per `--slurm-files-per-job` batch (each exporting `OMP_NUM_THREADS=${SLURM_CPUS_PER_TASK}`) plus a merge job with `--dependency=afterany` that fails if any batch is missing, incomplete or stale. For `--slurm` it builds the binary as `{bin_name}_{hash}` (hash of the source, `src/simple_json.h`, the OpenMP flags and `root-config --cflags --libs`) and reuses an existing one, so later invocations can neither overwrite nor delete the binary queued jobs execute; local runs build and remove the plain `{bin_name}`. `--slurm-account` (default `cms-express`) is passed as `sbatch --account`, `--slurm-partition` (default empty) as `--partition` and `--slurm-exclude` (default empty since 2026-10-05, when the formerly hanging Hammer nodes were fixed; the repo's sbatch scripts no longer exclude nodes either) as `--exclude`. Its run log is appended to, not truncated, so consecutive submissions keep their history.

`run.sh` also installs an `EXIT` trap that, after the job's final `finished` log line is written, copies the run-log into the program's configured output directory for every mode that has one — `mode=1` (`output_root`), `mode=2` and `mode=4` (per-tree `output_root` template expanded against `submit_trees`), and `mode=3`, `mode=5`, `mode=7` (`output_dir`). The destination filename is always `log.txt` inside that output dir; if a destination dir does not exist (e.g., the script aborted before creating it), the copy is skipped with a warning. `mode=0` (`convert_branch`) and `mode=6` (`mix`) are intentionally excluded. The copy happens both on success and failure so that the final log lines `[finished job=… status=…]` are always preserved, but the post-copy bookkeeping lines (`copied log to …`) only appear in the source `log.txt`, not in the copy. Path resolution mirrors the scripts themselves: relative `output_root` / `output_dir` values are resolved against each mode's `WORK_DIR`, which is the same directory each script uses as its `_SCRIPT_DIR`.

## C++ Expression Engine (convert_branch.C)

The selection and branch formulas in JSON are parsed by a mini expression engine inside [selections/convert/convert_branch.C](selections/convert/convert_branch.C). Supported syntax:
- Arithmetic/logical operators, comparisons
- Functions: `pt(obj)`, `eta(obj)`, `phi(obj)`, `mass(obj)`, `abs()`, `min()`, `max()`, `size(coll)`, `deltaR(a,b)`, `min_deltaR(self, coll)`, `relPtDiff(a,b)`
- Pairwise summaries `pair_{min,max}_{deltaR,deltaPhi}(coll, n)` over the first `n` objects; the `deltaPhi` variants use `|Δφ|` (the plain `deltaPhi(a,b)` function stays signed)
- Collection indexing: `ak8[0]`, `ak4[1]`
- `self` / `other` keywords in per-object selection strings

Evaluation and reading (rewritten for speed on 2026-10-02; outputs unchanged): the parser stores an operator/function code (`Op`) in every node, and `resolveEngineSymbols()`, called once in `main` after loading `branch.json` and `selection.json`, resolves all names. Event variables (input scalars, sample metadata, MC weights and the scalar output names of the tree being filled) live in the flat `EventVars` array indexed by `EventVarLayout` slot; the input and runtime collections of an event live in `EventCollections` vectors indexed by slot; every identifier node carries its variable and collection slots and its field index per object schema (`ObjectSchema::id`). Field schemas are built once and shared by all events (merged collections' schemas and per-child field maps are precomputed), sourced runtime collections are selected straight from the input collection without copying it first, output branches are resolved to indices when the trees are booked, and a `Value` holds a four-vector only for four-vector results. The identifier lookup order is unchanged: field of the current object, then event variable (a scalar output becomes readable once computed in the current tree), then a runtime collection already built in this event, then an input collection; the former raw-scalar fallback was unreachable (every input scalar is an event variable) and was dropped. Unknown collection sources, merge children and `deduplicate_against` references, and merge cycles, are now reported at startup instead of at the first preselected event. Before the event preselection, `processInputFile` reads only the branches of the scalars it uses, plus `Pileup_nTrueInt` for MC (pileup-weight sums over all events) and `run`/`luminosityBlock` for data without a `LuminosityBlocks` tree; the full entry is read only for events that pass, so low-pass-rate samples (low-HT QCD) skip decompressing all other branches. Checked on two input files per sample for `www`, `qcd_ht100to200`, `qcd_ht1000to1200`, `ttbar_semilep` and `data_2024`: every branch of every output tree is bitwise identical to the previous implementation, as are `raw_entries`, `weight_pu*_mean` and the processed lumis. Single-thread conversion times (run side by side on the same node) went from 31/26/459/78/36 s to 15/4.9/157/42/11 s for these samples; a 2-thread run gives the same events (qcd_ht1000to1200 fills an output tree for 98% of its events, so it is limited by the output formulas and by ROOT I/O: LZMA input decompression, `TTree::Fill` and ZSTD compression are about half of its time).

## Physics Context

- **Signal:** VVV hadronic decays — WWW, WWZ, WZZ, ZZZ, and VH(->WW) associated production
- **Trigger:** `DST_PFScouting_JetHT` scouting stream
- **Jets:** AK8 fat jets (`ScoutingFatPFJetRecluster`) and AK4 jets (`ScoutingPFJetRecluster2`)
- **Signal regions:** `fat2` (2 AK8 jets, ≥2 AK4 jets) and `fat3` (≥3 AK8 jets)
- **QCD background:** estimated with ABCD method using model score as discriminant
- **Pileup corrections:** three variations (nominal/low/high) for systematic uncertainty
